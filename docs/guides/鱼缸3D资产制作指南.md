## 0. 先记住这条边界

鱼缸不是一个“静态展示模型”，它同时承担四种职责：

1. **视觉外壳**：玻璃、边框、底座、底砂、灯具、装饰；
2. **模拟容器**：定义水面高度、缸底高度、鱼群和食物可以活动的范围；
3. **交互表面**：玻璃可敲击、水面可投喂、空白区可关闭；
4. **动画载体**：旋转时水面要产生有延迟的波动，灯光和焦散要跟着状态变化。

所以替换鱼缸时要坚持一个原则：

> **外观可以自由替换，功能水面必须单独保留为一个可变形网格。**

不要把“整缸 GLB”直接盖在现有场景上，也不要把水面并入玻璃或底砂。最稳妥的结构是“**装饰外壳 + 独立功能水体**”：外壳决定长什么样，水体决定动画和交互。

## 1. 当前鱼缸是怎样工作的

### 1.1 坐标、单位与真实尺寸

项目内部统一使用**米制、Y 轴向上、鱼缸局部坐标**。鱼缸的所有东西都挂在 `tank` 这个 `THREE.Group` 下；旋转只改 `tank.rotation.y`，不改水面顶点或鱼的世界坐标。

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| `SPACE.width` | `0.400 m` | 缸体外部总宽 |
| `SPACE.height` | `0.300 m` | 缸体总高 |
| `SPACE.depth` | `0.250 m` | 缸体外部总深 |
| `SPACE.waterY` | `0.267 m` | 静水面高度（局部 Y） |
| `SPACE.floorY` | `0.018 m` | 底砂上方、鱼群可用的最低活动面 |
| 内壁 X | `-0.193 ~ +0.193 m` | 净宽约 `38.6 cm` |
| 内壁 Z | `-0.118 ~ +0.118 m` | 净深约 `23.6 cm` |
| 水深 | `0.267 - 0.018 = 0.249 m` | 约 `24.9 cm` |

当前外形为 40 × 30 × 25 cm 的清透长方缸，水面距缸口约 3.3 cm，这是刻意留出的干舷，不要让水直接平到玻璃上沿。

`SPACE` 定义在 `src/core.js`；鱼缸网格在 `src/scene.js`；鱼群边界通过 `src/species.js` 的 `space: SPACE` 间接使用同一组数值。

### 1.2 场景对象的分层

```text
scene
└─ tank (Group，绕 Y 轴旋转)
   ├─ glassPanels       四片玻璃，userData.kind = 'glass'
   ├─ glassEdges        玻璃厚度边缘和角柱
   ├─ waterSurface      可变形水面，waterGeo
   ├─ waterHit          不可见、平坦的水面命中面，kind = 'water'
   ├─ waterVolume       水体色调壳体，BackSide + 透明着色器
   ├─ sand / grains     底砂、砂砾、石子
   ├─ caustics          底部的动态焦散
   ├─ lamp              灯杆、灯臂、灯头、灯管，见顶灯指南
   ├─ bubbles / food
   └─ fish schools      鱼群，使用 SPACE 作为活动边界
```

必须把壳体、水面、底砂、灯都放在 `tank` 内，才能达到“拖动旋转时水和灯一起转”的效果。不要把灯或水面挂到 `scene` 根节点上，否则旋转时会出现灯不跟着缸转、光域错位。

### 1.3 旋转 → 水波 → 光照的现有链路

```text
pointermove
  → Gesture.move()
  → sim.rotate(dx * 0.009)
  → sim.waveVelocity / sim.waveCrossVelocity 增加
  → Simulation.update(dt) 阻尼衰减
  → animateMaterials() 逐顶点改写 waterGeo.position.y
  → computeVertexNormals()
  → 水面高光、焦散、灯光强度在同一帧更新
```

关键点：

- `sim.yaw` 只作用于 `tank` 的旋转；
- 水波的相位使用 `tank` 局部坐标 `x/z`，旋转后不会因为世界坐标改变而跳变；
- 水面网格的顶点 `y` 是动画量，基准平面仍在 `waterY`；
- 水面命中面是独立的平坦面，不参与顶点动画，因此旋转和投食时射线始终稳定；
- 焦散时间 `uTime` 来自 `sim.time`，灯光强度来自 `light`，二者都不能在换壳时丢掉。

## 2. 哪些可以改，哪些不能碰

### 2.1 可以自由改

- 长宽高、圆角、缸壁厚度、缸口是否加框；
- 方缸、圆角缸、弧面缸、圆柱缸、六角缸、异形缸；
- 玻璃颜色、边框材质、底座材质、底砂颜色和颗粒；
- 是否有缸盖、灯架、夹灯、吊灯、长条灯或多灯头；
- 装饰物、造景石、沉木、水草，只要不遮挡水面和水面命中面；
- 鱼的品种、数量、泳层，前提是继续使用同一套 `SPACE` 或同步更新它。

### 2.2 必须保留

| 契约 | 位置 | 不保留的后果 |
| --- | --- | --- |
| 一个统一的 `tank` 组承载所有可见物体 | `src/scene.js` | 旋转时部分物体不跟着转，水和灯错位 |
| 一个可逐帧改顶点的水面网格 | `waterGeo` | 旋转不再有水波，或水波只有贴图没有几何变化 |
| 一个独立、平坦的水面命中面 | `kind: 'water'` 的 mesh | 投食射线漂移、旋转后点不到水 |
| 玻璃命中标记 | `userData.kind = 'glass'` | 敲击玻璃无反应或与空白区冲突 |
| 水面基准高度和缸底高度 | `SPACE.waterY / floorY` | 水溢出、鱼穿底、食物沉到缸外 |
| 焦散与灯光的时间/强度接线 | `causticMat.uniforms`、`light` | 换了灯以后光照变“死”，没有水波照射感 |
| 资源可通过 `own()` 释放 | `Resources` | 反复开关插件后 GPU 资源增长 |

### 2.3 不建议的做法

1. **把整缸模型直接 `scene.add()`**：会绕过 `tank` 的旋转和命中体系。
2. **用一张带水波法线贴图的平面替代几何水面**：贴图只改变着色，不会产生真实轮廓变化，旋转时的“水面倾斜/翻涌”会消失。
3. **把水面做得比缸口大再裁切**：容易在缸壁外看到方形的透明水面。
4. **再加一圈固定高度的“水线装饰条”**：旋转时它会暴露原来的静水位，形成穿帮直线。当前版本已经删掉这圈固定 meniscus，改为只让动态水面自己形成边缘。
5. **把水体做成不透明的实体**：会挡住鱼、底砂和背面的玻璃层次。

## 3. 路线 A：改尺寸，不换拓扑

这是风险最低的路线，适合先把 40 cm 缸改成 30、60 或 90 cm 缸，或者只改变长宽比例。

### 3.1 先改“单一尺寸源”

不要直接在很多网格上手改数值。先定义一个鱼缸参数对象，让玻璃、水面、命中面、底砂、焦散和相机都从它派生：

```js
export const TANK = Object.freeze({
  width: 0.40,          // 外宽，米
  height: 0.30,         // 总高
  depth: 0.25,          // 外深
  wall: 0.003,          // 玻璃厚度
  baseHeight: 0.006,    // 底玻璃/底座高度
  waterGap: 0.033,      // 水面到缸口
  sandDepth: 0.013,
});

const innerWidth = TANK.width - TANK.wall * 2;
const innerDepth = TANK.depth - TANK.wall * 2;
const waterY = TANK.height - TANK.waterGap;
```

然后把 `SPACE` 更新为同一组派生值，而不是只改画面：

```js
export const SPACE = Object.freeze({
  width: TANK.width,
  height: TANK.height,
  depth: TANK.depth,
  waterY,
  floorY: TANK.baseHeight + TANK.sandDepth,
  minX: -innerWidth / 2 + 0.001,
  maxX: innerWidth / 2 - 0.001,
  minZ: -innerDepth / 2 + 0.001,
  maxZ: innerDepth / 2 - 0.001,
});
```

实际项目里可以保留现有常量，只在 `core.js` 集中定义并导出；核心原则是**一个尺寸源，所有网格引用它**。

### 3.2 必须同步的网格

| 网格 | 当前尺寸来源 | 改尺寸时要做什么 |
| --- | --- | --- |
| 四片玻璃 | `0.4 × 0.3 × 0.003` 等 | 宽/深/高、位置按内壁重新计算 |
| 玻璃上下边缘 | `y = 0.004 / 0.299` | 跟随新高度，保留 1–2 mm 收边 |
| 水面 | `0.396 × 0.246`，`48 × 32` 段 | 按内宽内深调整，段数随面积增加 |
| 水面命中面 | `SPACE.maxX * 2 × SPACE.maxZ * 2` | 必须在新的内壁范围内 |
| 水体体积 | `0.394 × waterY × 0.244` | 只覆盖水下的内体积 |
| 底砂/砂面 | `0.39 × 0.24` | 跟随内底，不能穿出玻璃 |
| 焦散面 | `0.386 × 0.236` | 跟随底砂上表面，且不超出内壁 |
| 相机取景 | `fitDistance`、`focusY = 0.15` | 重新取景，保证缸体和灯都在画布内 |

### 3.3 网格段数预算

水面并不是顶点越多越好，但太少会让波浪变成折线：

| 缸体最长边 | 建议水面网格 | 说明 |
| --- | --- | --- |
| ≤ 40 cm | `48 × 32` | 当前值，约 1,600 顶点 |
| 40–70 cm | `64 × 40` | 让波长与网格间距匹配 |
| 70–120 cm | `80 × 52` | 同时观察省电模式下的帧率 |

省电模式会降低阴影、气泡、砂砾和焦散更新频率，但水面顶点循环仍应保持；如果水面本身成为性能瓶颈，优先降低网格段数，而不是停止水面更新。

### 3.4 改尺寸后的最小回归

```powershell
npm run check
npm run preview
```

至少要确认：

- 四片玻璃没有缝隙，底部玻璃与底座没有悬空；
- 水面在缸口以下，旋转到最大角度也不露出方形边缘；
- 灯头和灯臂没有被缸口切断；
- 投食落点仍在内壁范围内；
- 鱼群不会穿出新的内壁。

## 4. 路线 B：换成任意形状或样式

“任意形状”不等于“任意拓扑都能直接替换”。推荐把任何新鱼缸拆成两部分：

```text
新鱼缸 = 装饰外壳（可自由建模）
       + 功能水体（必须遵守本指南的契约）
```

### 4.1 先定义水体轮廓，而不是先做玻璃

在建模之前，先用二维平面画出一张“水面俯视轮廓”：

- 外轮廓：玻璃外壁；
- 内轮廓：玻璃内壁；
- 水面轮廓：内轮廓减去一个安全边距（通常 1–3 mm）；
- 若有圆弧、切角、弧面，先把内轮廓近似为可查询的多边形或参数曲线。

至少要能在代码里回答两个问题：

```js
// 某个局部坐标是否在可投食的水面内？
function insideWater(x, z) { /* ... */ }

// 水面边缘到内壁的安全距离是多少？
function waterEdgeMargin(x, z) { /* ... */ }
```

矩形缸可以直接沿用 `minX/maxX/minZ/maxZ`；圆角矩形、椭圆缸、圆形缸建议写一个 `insideWater` 判定，并用它驱动投食边界、鱼群边界和水面网格的裁切。

### 4.2 圆角矩形的最小实现

以圆角矩形为例，可以用 signed distance 判断内轮廓：

```js
function roundedRectSDF(x, z, halfW, halfD, radius) {
  const qx = Math.abs(x) - (halfW - radius);
  const qz = Math.abs(z) - (halfD - radius);
  const outside = Math.hypot(Math.max(qx, 0), Math.max(qz, 0));
  return outside + Math.min(Math.max(qx, qz), 0) - radius;
}

function insideWater(x, z) {
  return roundedRectSDF(x, z, innerWidth / 2, innerDepth / 2, cornerRadius) < -0.002;
}
```

这段判定的用途是“判断范围”，不是直接用 SDF 生成玻璃厚度。玻璃的可见厚度、倒角和圆角仍由建模决定；水体只关心内侧是否可容纳水。

### 4.3 装饰外壳怎样做

#### 方形/圆角缸

- 四片玻璃可以继续用薄盒体拼，四角用倒角或圆角过渡；
- 圆角处不要留垂直缝隙，角柱和边缘材质要连起来；
- 底玻璃与底砂之间保留一条暗色接触阴影，避免“底砂浮在玻璃上”；
- 玻璃上沿可以保留 1–2 mm 的亮边，但**不要再加水位的固定亮条**。

#### 圆柱/椭圆缸

- 玻璃用开口的圆柱/椭圆环，不要用封闭实体；
- 内壁法线要朝向缸内，否则 `DoubleSide` 虽然能看见，但高光和厚度会不对；
- 水面轮廓使用内椭圆，命中面也用同一轮廓；
- 底座和上沿的圆环必须与玻璃同心，避免转动时露出偏心缝。

#### 弧面/异形缸

- 建议把外壳作为独立 GLB/程序化网格，保留 `tank` 组作为父节点；
- 外壳可以有任何外形，但**不要在外壳里包含可动画水面**；
- 若外壳自带一块“装饰水”，把它设为不可见的静态面或移除，只保留功能水面；
- 玻璃厚度用真实几何或双层法线表现，不依赖单面材质的假厚度。

### 4.4 水面网格的两种可用做法

#### 做法 1：高密度矩形载波面（推荐，改动最小）

保留现有 `PlaneGeometry`，只把尺寸缩到内壁以内；如果外形是圆角或椭圆，使用材质的 alpha 裁切来隐藏轮廓外的区域，命中面与裁切使用同一轮廓。

优点：可以直接复用现有顶点波动代码，风险最低。

注意：透明水面的裁切边缘要与玻璃内壁对齐，且不能把裁切后的硬边暴露成白色锯齿；边缘处需要用低透明度渐变。

#### 做法 2：在 Blender 中做“可变形水面片”

如果需要完全贴合异形内壁：

1. 只做一张**平面网格**，局部坐标 XZ 展开，Y=0；
2. 网格原点放在水面中心，所有顶点在 Y=0；
3. 内部要有均匀细分，边缘不要只有一条长边；
4. 导出 GLB 时不要带相机、灯光、动画和材质节点；
5. 入项目后将该网格赋给 `waterGeo` 的同等角色，并继续执行逐顶点 Y 变形。

不推荐直接使用 `ShapeGeometry` 的默认三角化结果：它通常只有边界和少量三角形，中心没有足够顶点，波浪会变成大块折面。要么在 Blender 中细分，要么使用高密度矩形网格加轮廓裁切。

### 4.5 水面顶点动画的固定写法

无论水面来源是什么，最终都要保留这段逻辑的形状：

```js
const attr = waterGeo.attributes.position;

for (let i = 0; i < attr.count; i++) {
  const x = attr.getX(i);
  const z = attr.getZ(i);

  const micro = Math.sin(x * 70 + sim.time * 1.3)
    * Math.cos(z * 55 - sim.time)
    * (eco() ? 0.00018 : 0.00035);

  let ripple = 0;
  if (lastFeedPoint && rippleAge >= 0 && rippleAge < 1.4) {
    const distance = Math.hypot(x - lastFeedPoint.x, z - lastFeedPoint.z);
    ripple = Math.sin(distance * 260 - rippleAge * 17)
      * Math.exp(-rippleAge * 2.6 - distance * 9)
      * 0.0018;
  }

  const crossWave = sim.waveCross * 0.45
    * Math.cos(z * 24 - x * 7 - sim.time * 1.7);

  attr.setY(i, micro + ripple + crossWave
    + sim.wave * Math.sin(x * 18 + z * 8 + sim.time * 2.2));
}

attr.needsUpdate = true;
waterGeo.computeVertexNormals();
```

这段代码有三个隐含前提：

- 顶点局部 Y 的基准是 `0`，水面组的位置是 `waterY`；
- 顶点 X/Z 没有被烘焙到世界坐标，旋转由父组完成；
- 水面没有被合并进玻璃或静态装饰，否则无法逐帧更新。

如果换成 GLB 水面，先在加载后把几何烘焙到“中心为原点、Y=0、XZ 平面”的坐标，再交给同一段循环。不要直接对带旋转、缩放或非零原点的节点写 Y。

### 4.6 水体体积与色调

当前水体不是实体水，而是一个只渲染背面的透明壳体：

```js
new THREE.ShaderMaterial({
  transparent: true,
  depthWrite: false,
  side: THREE.BackSide,
  uniforms: { uDark: { value: dark ? 1 : 0 } },
  // fragment 根据局部 Y 做“越深越浓”的渐变
});
```

换形状时：

- 体积壳要跟随内轮廓，不要比玻璃更宽；
- 保持 `BackSide`、透明、`depthWrite: false`；
- 不要在顶部加一个固定盖面，否则旋转时会重新出现“旧水线”；
- 如果体积壳的几何 Y 范围不是 `[-0.5, 0.5]`，必须同步改 shader 里的深度归一化，否则颜色深浅会错。

### 4.7 底砂、焦散和装饰物

- 底砂上表面要略低于 `waterY`，同时高于 `floorY` 的鱼群最低活动面；
- 焦散面应该贴在底砂上方约 1–2 mm，不要贴到玻璃底面；
- 焦散只应出现在实际内底轮廓内，异形缸不要让方形焦散面露出玻璃外；
- 新加的石头、沉木、水草不能穿过水面动画区域；如果必须穿过，至少不要让它们参与水面命中；
- 新装饰物如果参与旋转，必须加入 `tank` 组；如果要参与点击，给它们明确的 `userData.kind`，不要让它们误判成玻璃或水。

---

## 5. 水面波动必须怎样保留

这一节是整份指南的硬约束。只要这里不出问题，外观怎么换都不会把“活缸”改成“静态模型”。

### 5.1 保留两套水面

| 面 | 用途 | 是否动画 | 是否可见 |
| --- | --- | --- | --- |
| `waterSurface` | 视觉水面、高光、反射、波浪轮廓 | 是 | 是 |
| `waterHit` | 投食/点击的射线命中 | 否 | 否（`colorWrite: false`） |

不要把两者合并。可见水面每帧顶点变化，射线如果直接打它，投食会随波纹漂移；反之，如果只留命中面而没有可见水面，就没有波浪。

### 5.2 旋转必须作用在父组

```js
tank.rotation.y = sim.yaw;
```

不要改成旋转相机，也不要旋转水面自身。旋转相机虽然看起来也像“缸在转”，但会让灯、背景、投影和鱼的世界位置关系改变，而且会破坏局部命中坐标。

### 5.3 水面边界不能超出内壁

水面网格应比内壁小 1–3 mm。若水面顶点在 X/Z 上超出玻璃，旋转到侧面时就会看到“水从玻璃里穿出去”或者方形水面边缘。

### 5.4 不要恢复固定水线

当前版本删除了四条固定高度的 meniscus 细线。它们不随顶点波动，旋转时会在原水位留下直线。正确的水面边缘由以下东西共同形成：

- 水面本身的几何边缘；
- 玻璃内壁的反射/折射边缘；
- 水体体积壳的顶部透明过渡；
- 灯光在边缘产生的细高光。

如果确实需要“弯月面”，必须让它跟随水面边缘顶点，而不是固定在 `waterY`。

### 5.5 波幅与安全范围

现有模拟的波幅上限：

- 主波 `wave`：约 `±0.011 m`；
- 交叉波 `waveCross`：约 `±0.007 m`；
- 投食局部涟漪：约 `±0.0018 m`。

新增水面网格或改变尺寸后，不要把波幅直接按比例放大。先保持这组上限，确认玻璃干舷足够，再考虑微调。

## 6. 灯光、焦散与鱼群的接线

### 6.1 顶灯不是静态装饰

顶灯的光束、灯管自发光、聚光灯和焦散都由 `animateMaterials()` 每帧更新。换鱼缸外壳时，**不要删除或重命名**这些对象：

```js
spot.intensity = light * 0.44;
bulbMat.emissiveIntensity = 0.08 + light * 2.6;
beamMat.uniforms.strength.value = light * (dark ? 0.85 : 0.28);
causticMat.uniforms.uTime.value = sim.time;
causticMat.uniforms.uStrength.value =
  ((dark ? 0.12 : 0.22) + light * (dark ? 0.85 : 0.48)) * (eco() ? 0.65 : 1);
```

如果新灯需要不同的发光颜色或强度，改参数，不要删掉接线。详细结构见[顶灯指南](./鱼缸顶灯3D资产制作指南.md)。

### 6.2 焦散与水面是“同一条时间线”

当前焦散不是逐顶点计算折射，而是：

- 使用 `sim.time` 驱动一张程序化焦散纹理的相位；
- 使用 `light` 控制亮灯时的强度；
- 贴在底砂上方，形成低对比度的移动光斑。

这个实现牺牲了物理精确性，换来了低开销和稳定观感。替换鱼缸时请保留这条时间线；不要用 `Date.now()` 或 CSS 动画驱动焦散，否则暂停、隐藏、恢复时相位会跳变。

### 6.3 鱼群边界

鱼群使用 `species.space`，最终指向 `SPACE`。如果新鱼缸内壁变小，必须同步收紧：

```js
minX / maxX / minZ / maxZ
floorY + 0.022
waterY - 0.018
```

否则鱼会穿玻璃、贴底或跃出水面。换缸后先看鱼，不只看玻璃。

## 7. 推荐制作流程

### 第 1 步：冻结基线

先保存当前可运行版本，截一张浅色、一张深色、一张旋转后的近景。后续每次换壳都对照这三张图，避免“新外形很漂亮，但水不动了”。

### 第 2 步：定尺寸和轮廓

先写 `TANK` 参数和 `insideWater`，再建模。不要在 Blender 里凭感觉做一个壳，再回来猜水面应该多大。

### 第 3 步：做装饰外壳

- 玻璃、边框、底座先完成；
- 外壳只负责“看起来像缸”，不负责模拟；
- 所有可见部件挂到 `tank`；
- 暂时不要加水面和鱼。

### 第 4 步：接入功能水体

- 创建/替换 `waterGeo`；
- 水面基准 `y = 0`，父节点放到 `waterY`；
- 保留顶点动画和 `computeVertexNormals()`；
- 单独创建同轮廓的平坦命中面；
- 检查旋转时的边缘和波幅。

### 第 5 步：接入底砂、焦散和灯

- 底砂上表面跟随新内底；
- 焦散面贴合底砂，不露出外壳；
- 灯继续挂在 `tank`，保持聚光灯目标、光束和自发光接线；
- 深色/浅色都看一遍。

### 第 6 步：回归

```powershell
npm run check
npm run preview
```

再手动做一次旋转、一次投食、一次玻璃敲击。不要只截静图。

## 8. 验收清单

### 8.1 几何

- [ ] 四壁/曲面没有可见裂缝；
- [ ] 底玻璃、底座、底砂没有悬空或穿插；
- [ ] 水面边缘不超过内壁；
- [ ] 缸口干舷保留，旋转到最大角度不溢水；
- [ ] 灯架、灯头没有被缸体裁切。

### 8.2 水面

- [ ] 旋转时水面有延迟波动，不是整块刚性转动；
- [ ] 停止拖动后 2–4 秒内衰减到微波；
- [ ] 没有固定高度水线、方形水面边缘或明显折线；
- [ ] 近景没有大三角折面、Z-fighting、白色锯齿；
- [ ] 投食位置出现局部涟漪，且涟漪不超出缸口。

### 8.3 交互

- [ ] 玻璃区域显示手型并可敲击；
- [ ] 水面区域投食命中稳定，旋转后仍能投到正确位置；
- [ ] 墙外/缸外投食被拒绝；
- [ ] 拖动不会误触敲击或投食；
- [ ] 鱼群不穿玻璃、不穿底砂、不跃出水面。

### 8.4 灯光与性能

- [ ] 深色自动亮灯，手动关闭后恢复；
- [ ] 灯管、光域、底砂焦散同步亮灭；
- [ ] 长条灯不是圆锥光束，光束方向与灯管一致；
- [ ] 标准质量下目标 60 FPS，省电模式不出现明显闪烁；
- [ ] 连续开关插件后 GPU 几何/纹理数量不持续增长。

## 9. 常见问题与修复

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 旋转后出现一条固定水平线 | 还在使用固定 `waterY` 的 meniscus/装饰条 | 删除固定线，或让它跟随水面边缘顶点 |
| 水面像一块方形玻璃板 | 水面网格超出异形内壁，或没有按轮廓裁切 | 缩小网格并用同一轮廓裁切；命中面同步 |
| 水面完全不动 | 把水面换成了静态 GLB/贴图面 | 保留可写 `position` 的网格，接回逐顶点 Y 循环 |
| 水面动但边缘穿出玻璃 | 水面尺寸大于内壁 | 按内壁减 1–3 mm 重设 |
| 投食点漂移 | 直接对可见的波动水面做 raycast | 保留独立平坦 `waterHit` |
| 鱼穿出缸壁 | 只改了玻璃，没有同步 `SPACE` | 同步内壁、`waterY`、`floorY` 和鱼群边界 |
| 灯不跟着缸转 | 灯挂在 `scene` 或独立 group | 把灯和灯目标都挂到 `tank` |
| 深色下水面发白 | 水体/玻璃透明层叠加过多，或曝光过高 | 降低水体 alpha、玻璃 fresnel 和曝光，先看深色截图 |
| 焦散在异形缸外出现方块 | 焦散仍是矩形平面 | 按内底轮廓裁切，或缩小到内底以内 |
| 换缸后帧率下降 | 水面段数、玻璃透明层或阴影 map 过大 | 先降水面段数和透明层数，再考虑阴影分辨率 |
