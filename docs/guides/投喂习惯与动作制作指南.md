## 0. 先记住五条设计约束

1. **食物是全缸共享的，行为是每条鱼独立的。** `FeedingDirector` 只协调食物目标和占用；每条鱼有自己的 `FeedingBehavior`，所以发现时间、接近角度和抢食结果可以不同。
2. **行为状态和运动控制分开。** `FeedingBehavior` 决定“现在想干什么”，真正的加速、转向、限速仍由红绿灯的路径控制器或小丑鱼的 `ClownfishPilot` 完成。
3. **受惊优先于吃食。** 先更新 `StartleBehavior`；受惊期间暂停觅食并释放食物占用，平复后才重新发现剩余颗粒。
4. **不要直接改位置来“做动作”。** 动作应由速度差、加速度、转向角速度和缓动构成，位置只在边界约束时夹紧。直接设坐标会瞬移。
5. **一次敲击只响应一次。** 敲击事件会在 `Simulation.taps` 中保留约 0.7 秒用于光圈动画；鱼通过 `WeakSet` 记住已听过的对象，不能按数组长度判断新事件。

### 0.1 这轮实现的关键取舍

| 原始问题 | 采用的做法 | 为什么不选更简单的做法 |
| --- | --- | --- |
| 鱼食会下沉，但鱼完全不读食物 | 行为层主动读取共享食物列表，吃食时原子消费 | 只让颗粒到时间消失，是假吃食，用户一眼能看出 |
| 所有鱼容易扑向同一粒 | `FeedingDirector` 记录占用，并在选目标时加争抢惩罚 | 全用随机目标会失去“抢同一粒”的戏剧性 |
| 敲缸只有光圈，鱼没反应 | 每条鱼独立 `StartleBehavior`，按距离延迟并朝外逃 | 全缸统一抖动像特效，不像活鱼 |
| 鱼正在抢食时被敲击 | 受惊优先，先释放食物占用，平复后重新发现 | 两套动作同时抢控制权会抽搐、折返 |
| 投喂指针仍是系统十字 | 32×32 内联 SVG 小罐，两档倾角 + 固定热点 | 外链图片会增加请求和打包复杂度，系统 `grab` 无法表达“倒食” |

## 1. 系统组成与数据流

```text
鼠标/触控板
  ├─ 观赏模式单击玻璃
  │    └─ sim.tap(point, normal, now)
  │         └─ taps[] ───────────────┐
  │                                  │
  └─ 投喂模式单击水面                 │
       └─ sim.feed(point, now)        │
            └─ food[] ───────┐        │
                              ▼        ▼
固定步长 1/60 更新
  sim.update(dt)：食物下沉、淡出、敲击事件过期
  School.update(dt, feedingDirector, sim.taps)
       ├─ StartleBehavior.update(...)      受惊优先
       ├─ FeedingBehavior.update(...)      仅在未受惊时
       └─ 品种运动控制器
            ├─ 红绿灯：解析群游路径 + 觅食/受惊位移 + 回融
            └─ 小丑鱼：ClownfishPilot 的速度、转向、侧倾
```

### 1.1 文件职责

| 文件 | 负责什么 | 不应做什么 |
| --- | --- | --- |
| `src/core.js` | 食物生成、下沉、消费、敲击节流与事件生命周期 | 不决定鱼怎么游 |
| `src/feeding.js` | 共享目标选择、食物占用、`notice → gather → compete → scatter` | 不直接改鱼的位置 |
| `src/startle.js` | 每条鱼的 `alert → flee → settle → calm`、逃逸目标与强度 | 不处理鱼种转向差异 |
| `src/fish.js` | 鱼群加载、每鱼行为实例、红绿灯运动、受惊与觅食优先级 | 不重复实现小丑鱼转向 |
| `src/clownfish.js` | 小丑鱼领地、巡游、冲刺、限速转向和泳姿 | 不管理食物占用 |
| `src/scene.js` | 输入仲裁、投喂/敲击接线、光标切换、快照与资源释放 | 不藏第二套行为逻辑 |
| `src/feed-cursor.js` | 两种罐形 SVG 指针及热点 | 不判断当前是否可投喂 |

### 1.2 不可破坏的调用顺序

```js
// 每条鱼的顺序必须是：受惊 → 必要时打断觅食 → 觅食决策 → 运动控制
const startle = f.startle.update(dt, { position, taps, space });
if (startle.justTriggered) {
  f.feeding.interrupt(director, key);
  f.returnFrom = null;
}
const feeding = startle.active ? null : f.feeding.update(dt, {
  key, position, director, space, eatRadius, approachRadius,
});
moveFish(feeding, startle);
```

把 `feeding.update()` 放在受惊判断之前，会出现“鱼已经逃跑但还在吃远处的颗粒”；把运动控制放在状态更新之前，会晚一帧，快速转向时尤其明显。

## 2. 投喂习惯：从落食到散开

### 2.1 食物生命周期

当前投喂规则在 `src/core.js`：

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| `LIMITS.batch` | 4 | 手动点击鱼食罐一次投入的颗粒数 |
| `LIMITS.feedMs` | 150ms | 连续手动投喂的最小间隔 |
| `LIMITS.food` | 100 | 缸内同时存在的食物上限 |
| `LIMITS.life` | 25s | 未吃完颗粒的寿命，最后 3 秒淡出 |
| 初始下落速度 | 0.022～0.034 | 每粒略有差异，向下沉降 |
| 水平漂移 | 约 0.0012～0.0016 | 由正弦扰动产生，避免垂直下落 |
| 落点散布 | ±0.007 | 一批颗粒不会完全重合 |

食物只在 `state === 'active'` 时可被选择。`Simulation.consume(id)` 会原子删除，重复 ID 或已被吃掉的 ID 返回 `false`，所以两条鱼同时扑向同一粒时只会有一条成功。

### 2.2 共享目标协调器

`FeedingDirector` 做三件事：

- `nearest(position)`：找最近的有效颗粒，用于“发现”和计算响应延迟。
- `select(position, key)`：在距离分上加入争抢惩罚，避免所有鱼锁死同一粒。
- `claim(key, id)` / `release(key)`：记录哪条鱼占了哪粒；进食成功后释放。

选择分数当前为：

```text
score = 鱼与颗粒距离 + 其他争抢者数量 × 0.042
```

`0.042` 是“绕路成本”。调大，鱼更愿意分散到不同颗粒；调小，鱼更集中，抢食更激烈。只剩一粒时，占用惩罚不会阻止所有鱼赶来争抢，这是刻意保留的戏剧性。

### 2.3 单鱼觅食状态机

| 状态 | 行为含义 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| `cruise` | 正常巡游，不关心食物 | 初始/散开结束 | 缸里出现食物 |
| `notice` | 发现食物，短暂悬停并转向 | 从 `cruise` 或抢食失败进入 | 延迟结束 |
| `gather` | 向分配到的颗粒接近 | `notice` 结束并成功占用 | 进入争食半径 |
| `compete` | 近距离探头、错身、争抢 | 距颗粒 ≤ `competeRadius` | 吃掉、被抢或食物消失 |
| `scatter` | 吃空后分组散开 | 食物耗尽 | 3.2～4.6 秒后回游 |

发现延迟公式：

```text
delay = clamp(0.18 + 鱼与最近食物距离 × 1.7 + 随机 0～0.22, 0.25, 1.0)
```

因此近处鱼先动、远处鱼后动，但所有鱼会在约 1 秒内开始响应。这个公式比“全缸统一延迟”自然，也比逐条随机更可解释。

### 2.4 吃食、失手与散开

- 红绿灯吃食半径 `0.021m`，接近半径 `0.014m`；小丑鱼分别为 `0.029m` 和 `0.024m`。大鱼嘴部活动范围更大，所以数值不同。
- 目标被别的鱼吃掉后，会先进入约 `0.12～0.32s` 的短暂悬停，再重新选目标，不会立刻原地换向。
- 最后一粒被吃空后，鱼按 `index % 3` 分成三组，朝不同方向散开；散开目标有随机距离与个体错位。
- 红绿灯散开的最后 `1.15s` 会从当前位置平滑融回解析群游路径，避免“散开结束瞬间跳回原位”。

### 2.5 可调参数总表

| 想改变什么 | 参数 | 位置 | 当前值 | 调大的效果 | 风险 |
| --- | --- | --- | ---: | --- | --- |
| 发现更慢/更迟疑 | `FEEDING.noticeMin/Max` | `src/feeding.js` | 0.25 / 1.0 | 更从容，互动反馈变弱 | 超过 1.5s 会显得没看见 |
| 更早进入争抢 | `FEEDING.competeRadius` | `src/feeding.js` | 0.055 | 抢食动作更提前、更热闹 | 鱼在离颗粒较远时就开始挤 |
| 散开更久 | `FEEDING.scatterMin/Max` | `src/feeding.js` | 3.2 / 4.6 | 饱食后的余韵更长 | 太久会像迷路 |
| 更容易吃到 | `eatRadius` | `src/fish.js` | 红 0.021 / 小 0.029 | 降低“嘴边吃不到” | 过大会隔空吸食 |
| 接近角度更散 | `approachRadius` | `src/fish.js` | 红 0.014 / 小 0.024 | 减少头部重叠 | 过大会绕着颗粒转 |
| 游得更快 | 各状态 `maxSpeed` | `src/fish.js` / `src/clownfish.js` | 见 §4 | 更急切 | 穿景、转向生硬 |
| 一次投更多 | `LIMITS.batch` | `src/core.js` | 4 | 更热闹 | Token 投放仍是 5 粒/批，探针和文案需同步 |
| 食物更耐吃 | `LIMITS.life` | `src/core.js` | 25 | 有更多时间发现 | 残留更久，视觉变脏 |
| 限制总食量 | `LIMITS.food` | `src/core.js` | 100 | 能堆更多 | 性能与画面都会变拥挤 |

> 只改一个“感觉参数”时，优先从某一物种的运动速度或发现延迟开始，不要同时改半径、速度和转向。否则一次回归里无法判断是哪一个造成的变化。

## 3. 常见投喂口味改法

下面三种“口味”都只需改少量参数。改完必须更新对应单元测试的边界，否则测试会正确地拦住你。

### 3.1 更急切：像饿了很久

适合用户希望点击后马上有反馈的版本：

```js
// src/feeding.js
export const FEEDING = Object.freeze({
  noticeMin: 0.15,
  noticeMax: 0.6,
  competeRadius: 0.065,
  scatterMin: 2.4,
  scatterMax: 3.4,
});
```

同时在 `src/fish.js` 中把红绿灯 `gather` 速度从 `0.108` 提到约 `0.125`，小丑鱼 `gather` 从 `0.145` 提到约 `0.165`。速度提升不要超过 25%，否则接近颗粒时刹车距离不足，鱼头会来回越过目标。

**需要同步的测试**：`tests/feeding.test.mjs` 中“near fish ...”用例目前断言最晚响应不超过 `1.02s`，更急切版本仍能通过；改成更迟缓版本时要调大这个上限。

### 3.2 更从容：先观察，再慢慢靠近

```js
export const FEEDING = Object.freeze({
  noticeMin: 0.6,
  noticeMax: 1.4,
  competeRadius: 0.042,
  scatterMin: 4.2,
  scatterMax: 5.8,
});
```

再把红绿灯 `gather` 速度降到约 `0.085`、小丑鱼降到约 `0.115`，并适当增大 `approachRadius`。这一版适合“工作台里的安静鱼缸”，但发现延迟超过约 1.5 秒后，用户会误以为投喂没有生效。

### 3.3 减少叠鱼：让每条鱼有自己的接近位

按当前实现调这三处最有效：

1. `approachRadius`：红绿灯 `0.018～0.022`，小丑鱼 `0.028～0.034`。
2. `FeedingDirector.select()` 的争抢惩罚：`0.042 → 0.055～0.065`。
3. `src/fish.js` 觅食阶段的个体斥力：当前半径 `0.044`、强度 `0.022`，可提到 `0.05` / `0.028`。

不要用“每条鱼固定一个方向”解决重叠，因为颗粒位置一直在变。接近角应由 `index` 的黄金角分散，再由局部斥力微调，这也是当前 `approachPoint()` 的做法。

### 3.4 改变每次投喂数量

手动批量由 `LIMITS.batch` 控制：

```js
// src/core.js
export const LIMITS = Object.freeze({
  food: 100, batch: 4, autoFeedBatch: 5, feedMs: 150,
  tapMs: 300, life: 25, step: 1 / 60,
});
```

改 `batch` 会同时影响：全屏提示、`probe:feeding` 中“首批 4 粒”的断言、README 的交互表，以及用户对“一次投多少”的预期。Token 自动投喂使用独立的 `autoFeedBatch = 5`，不要把它一起改掉，兑换规则仍按 5 粒整批发货。

### 3.5 给鱼加“性格”而不是全缸同一套参数

如果后续要开放多品种自定义，建议把习惯做成数据，而不是继续在 `fish.js` 里堆 `if`：

```js
// 设计示例，当前版本尚未接入用户配置
const TEMPERAMENT = {
  bold:   { notice: 0.65, eat: 1.0, flee: 0.75, settle: 0.8 },
  timid:  { notice: 1.35, eat: 1.2, flee: 1.15, settle: 1.45 },
  greedy: { notice: 0.55, eat: 0.85, flee: 0.9, settle: 1.0 },
};
```

然后只把倍率乘进已有参数：

```js
noticeDelay *= profile.notice;
eatRadius *= profile.eat;
fleeDuration *= profile.flee;
settleDuration *= profile.settle;
```

这样做的好处是：同一套状态机、同一套测试，只换数据。不要为“胆小型鱼”复制一份新的行为类。

## 4. 动作制作：让行为看起来像鱼

### 4.1 一个可信动作由三段组成

无论觅食还是受惊，都建议遵守同一套动作语法：

1. **预备**：短暂停顿、转向或收鳍，让观众知道“它注意到了”。
2. **主动作**：加速、冲刺、急转，速度变化要明显快于预备阶段。
3. **恢复**：减速、回正、融回巡游，不能瞬间切回原状态。

当前实现中：

- 觅食的预备是 `notice`，主动作是 `gather/compete`，恢复是 `scatter` 最后 1.15 秒的融合。
- 受惊的预备是 `alert`，主动作是 `flee`，恢复是 `settle` 后的 1.05 秒回融。

### 4.2 红绿灯：路径是底稿，行为是偏移

红绿灯的“正常位置”由 `School.pathAt()` 的解析路径给出，包含椭圆巡游、垂直起伏和个体泳层偏移。动作不是替换整条路径，而是临时离开路径：

- 觅食时由食物目标驱动，靠近后减速；吃完散开，最后融回路径。
- 受惊时由逃逸目标驱动，平复后用 `startleReturnTime` 在 1.05 秒内从当前位置 lerp 回路径。
- 回融使用 `smoothstep`（`p²(3-2p)`），起步和结束都平缓，不会一恢复就弹回。

各状态的目标速度：

| 状态 | 红绿灯速度 | 小丑鱼速度 |
| --- | ---: | ---: |
| `notice` | 0.008（几乎悬停） | 0.008 |
| `gather` | 0.108 + 个体巡游速度 × 0.014 | 0.145 |
| `compete` | 0.083 + 个体巡游速度 × 0.009 | 0.105 |
| `scatter` | 0.062 | 0.065 |
| 受惊 `alert` | 0（急停观察） | 0 |
| 受惊 `flee` | 0.19 + 强度 × 0.075 | 0.23 + 强度 × 0.04 |
| 受惊 `settle` | 0.055 | 0.05 |

红绿灯在争食时会叠加左右小幅修正（约 `0.0045`），制造探头和错身；受惊急逃时叠加约 `0.009` 的高频摆动。两类摆动都不应超过目标速度的 15%，否则会变成抖动。

### 4.3 小丑鱼：限加速度比“速度大”更重要

`ClownfishPilot` 的观感来自四个量同时变化：

| 参数 | 普通巡游 | 觅食 | 受惊急逃 | 作用 |
| --- | ---: | ---: | ---: | --- |
| 目标速度 | 0.022～0.20 | 0.008～0.145 | 0.23～0.27 | 决定动作规模 |
| 速度响应 `response` | 2.6 | 4.4 | 9～11 | 决定起速有多“弹” |
| 最大转向 `maxTurn` | 1.4～3.6 rad/s | 4.8 rad/s | 5～8 rad/s | 决定急转有多利落 |
| 转弯侧倾上限 | 0.42 rad | 同左 | 同左 | 决定身体有没有“重量” |

如果只想让鱼更活泼，先增大 `response` 和 `maxTurn`，不要先增大目标速度。速度很大但转向慢，鱼会绕大圈；响应快但转向大，才像小鱼突然受惊。

### 4.4 受惊动作的完整参数

`src/startle.js` 的状态转换：

| 状态 | 持续时间 | 运动表现 |
| --- | --- | --- |
| `alert` | 0.02～0.14s | 短暂急停、收势，准备朝外逃 |
| `flee` | 0.55～0.9s | 远离敲击点加速，摆尾幅度提高 |
| `settle` | 1.25～1.85s | 减速、降低摆尾，逐渐回到巡游 |
| `calm` | — | 无受惊目标，回到正常行为 |

关键公式：

```text
反应延迟 = clamp(0.018 + 距离 × 0.24 + 随机 0～0.035, 0.02, 0.14)
受惊强度 = clamp(1.08 - 距离 × 1.35, 0.55, 1)
逃逸距离 = (0.115 + 随机 0～0.055) × 受惊强度
```

- 垂直方向权重只有 `0.32`，因为玻璃敲击主要来自侧前方，鱼应更多横向逃离。
- 每条鱼额外带随机切向偏移（约 ±0.42）与三层泳层错位（±0.019），避免全群沿一条直线逃跑。
- 受惊目标被夹在水体内部，并与造景碰撞一起约束；不会为了“逃得远”穿出玻璃。

### 4.5 想做“胆小”“大胆”“迟钝”三种鱼

| 想要的感觉 | 调整 | 不建议 |
| --- | --- | --- |
| 胆小 | 反应延迟上限降到 0.08，逃逸距离增 20%，settle 延长到 2.2～2.8s | 同时提高速度和转向，会显得惊恐过度 |
| 大胆 | 受惊强度下限降到 0.35，逃逸距离减 30%，settle 缩到 1.0～1.4s | 直接把强度设为 0，敲缸就完全没有反馈 |
| 迟钝 | 反应延迟整体乘 1.6，alert 阶段延长 | 只把速度降低，鱼会“慢慢地被吓到”，不符合生物直觉 |

这些差异应通过 `StartleBehavior` 的构造参数或品种倍率实现，而不是复制状态机。

## 5. 接入一种新鱼

### 5.1 先判断它属于哪种运动骨架

| 类型 | 现有例子 | 运动方式 | 需要复用 |
| --- | --- | --- | --- |
| 群游型 | 红绿灯 | 解析路径 + 行为位移 + 回融 | `School.pathAt()`、`returnFrom` |
| 领地型 | 小丑鱼 | 目标跟踪 + 限加速度 + 限转向 | `ClownfishPilot` |
| 底栖/爬行型 | 暂无 | 贴底移动 + 障碍绕行 | 需新增控制器，不要硬套鱼群路径 |

前两种已经把觅食和受惊接线做完了。新增同类鱼主要是补配置、资产和品种分支，不需要再写一套投喂逻辑。

### 5.2 五步接入清单

**第一步：在 `src/species.js` 加品种数据。**

```js
export const SPECIES = {
  // …保留已有条目…
  myFish: {
    id: 'my-fish',
    name: '我的鱼',
    targetLength: 0.045,
    count: 3,
    facing: -1,
    axis: { along: 0, lift: 1, dorsal: 1 },
    rig: 'generic',
    textured: true,
    cruise: 0.78,
    heightBase: 0.105,
    heightStep: 0.024,
    space: SPACE,
  },
};
```

`targetLength` 必须按缸内净空控制，单条建议不超过 8cm，群游建议不超过 6.4cm。`facing` 和 `axis` 由资产实际朝向决定，不能照抄。

**第二步：在 `src/scene.js` 的 `schools` 数组注册资产。**

先在文件顶部导入 GLB（构建脚本已支持 `.glb` 二进制内联），然后追加一条 `schools` 记录：

```js
import myFishGlb from '../assets/my-fish.glb';

const schools = [
  { school: new School(tank, SPECIES.neonTetra, { collision: scape.collision }), source: neonTetraGlb, ready: false },
  { school: new School(tank, SPECIES.clownfish, {
      seed: 2.35, collision: scape.collision, feedingIndexOffset: SPECIES.neonTetra.count,
    }), source: clownfishGlb, ready: false },
  { school: new School(tank, SPECIES.myFish, {
      seed: 4.1, collision: scape.collision,
      feedingIndexOffset: SPECIES.neonTetra.count + SPECIES.clownfish.count,
    }), source: myFishGlb, ready: false },
];
```

`feedingIndexOffset` 必须接在已有鱼总数之后，用来生成稳定且不重复的行为 index。`key` 本身已经带物种 id，index 只影响泳层、接近角和逃逸分组。

**第三步：在 `School.load()` 内创建行为实例。**

当前每条鱼已经统一创建：

```js
feeding: new FeedingBehavior(this.feedingIndexOffset + i, 101 + i * 53 + this.seedParts * 100),
startle: new StartleBehavior(this.feedingIndexOffset + i, 307 + i * 71 + this.seedParts * 100),
```

若新鱼不需要特殊资产处理，走通用 `else` 分支即可。若需要独立骨骼或材质，再仿照 `clownfish` / `neon-tetra` 增加 `rig` 分支；**行为实例不要写在 rig 分支里**，否则某种骨骼就会漏掉觅食和受惊。

**第四步：让运动控制器消费 `feeding` 与 `startle`。**

群游型沿用红绿灯的四段逻辑：受惊 → 散开回融 → 觅食 → 正常路径。领地型给 `ClownfishPilot.update()` 增加 `startle` 参数，并遵守：

```text
受惊激活 ⇒ feedingActive 必须为 false
alert 速度接近 0，flee 最高，settle 低
反应速度：alert/flee 高于觅食，settle 低于觅食
```

**第五步：补快照与资源释放。**

`src/scene.js` 的 `fishState` 至少输出 `behavior`、`feeding`、`reaction`、`startles`、`eaten`；`School.dispose()` 要调用 `f.startle.dispose()`。否则长时间切换造景后，旧鱼的行为对象和 WeakSet 不会被一起清掉。

### 5.3 新鱼接入的验收顺序

1. **纯逻辑**：不加载 GLB，直接单独实例化并测试 `FeedingBehavior` 和 `StartleBehavior`，确认状态能走完。
2. **单鱼入缸**：先把 `count` 设为 1，检查尺寸、朝向、碰撞和回融。
3. **群体**：把数量恢复到设计值，观察是否重叠、是否全部同时转向。
4. **混合缸**：确认新鱼能和其他物种争同一粒食物，且受惊时不会互相穿过。

## 6. 制作自定义鱼食罐指针

### 6.1 当前指针的结构

`src/feed-cursor.js` 生成一个 32×32 的内联 SVG，并输出为 CSS `cursor`：

```js
export function createFeedCursor(angle) {
  return `url("data:image/svg+xml,${encodeURIComponent(jarSvg(angle))}") 7 7, pointer`;
}

export const FEED_CURSOR = createFeedCursor(-18);        // 进入投喂模式
export const FEED_CURSOR_WATER = createFeedCursor(-54);  // 命中可投喂水面
```

三个关键点：

- `7 7` 是**热点坐标**，表示实际落点对应图标左上角往右 7px、往下 7px，正好在罐口附近。
- `rotate(..., 16 16)` 围绕 32×32 画布中心旋转；只改角度不会让图标跳位。
- 末尾的 `pointer` 是浏览器不支持 SVG 光标时的回退形状，不能省略。

`src/scene.js` 根据当前命中的物体选择光标：

```text
投喂模式 + 命中水面  → FEED_CURSOR_WATER
投喂模式 + 其他位置  → FEED_CURSOR
观赏模式 + 命中玻璃  → pointer
观赏模式 + 水面/缸体 → grab
其他                 → default
```

退出投喂、指针取消、窗口失焦时都会恢复到 `default`。

### 6.2 换成自己的图标

**最小改法：只换角度和图形，不改接口。**

- 静态投喂：把 `-18` 改成 `-12～-24`，表现“拿着罐子”。
- 水面上方：把 `-54` 改成 `-45～-65`，表现“准备倾倒”。
- 两个角度的差值建议保持 **30～40 度**，否则用户很难从指针判断当前是否可以投喂。

**换图形：保持 32×32 画布和罐口位置。**

```js
function myCursorSvg(angle) {
  return `<svg xmlns="http://www.w3.org/2000/svg" width="32" height="32" viewBox="0 0 32 32">
    <g transform="rotate(${angle} 16 16)" stroke-linecap="round" stroke-linejoin="round">
      <!-- 你的图形：建议保留清楚的轮廓和 2px 以上描边 -->
    </g>
  </svg>`;
}
```

替换后必须同步：

1. 热点坐标 `7 7` 是否仍落在“出水口”。
2. `tests/feeding.test.mjs` 中两个 `rotate(...)` 断言。
3. 在全屏视图里实际移动鼠标，确认图标在浅色和深色背景下都看得清。

**不要用 emoji 当指针。** 不同系统的 emoji 字体差异很大，热点也无法稳定控制。**也不要把未编码的 `#`、`<`、`"` 直接塞进 `url()`**，必须经过 `encodeURIComponent()`；否则 CSS 会把颜色值或标签截断。

### 6.3 修改指针状态逻辑时要守住的边界

- 进入投喂模式后，指针要立刻变化，不能等鼠标移动。
- 只有命中真实水面才用“倾倒”角度；命中玻璃、布景或空白仍是普通罐形。
- 退出投喂、按 `Esc`、指针取消、窗口失焦，都必须恢复默认。
- 拖动缸体时优先显示 `grabbing`，不要让投喂光标覆盖拖动反馈。
- 触屏没有 hover，不要在 `pointermove` 之外假设指针一定存在。

## 7. 调参与验收工作流

### 7.1 推荐的五步法

1. **固定场景**：使用 `?ledger=returning` 打开预览，避免初装 5 粒鱼食自动落缸干扰观察。
2. **先改一层**：只改发现延迟、速度或斥力中的一项，记下旧值。
3. **跑纯逻辑**：`npm test`，确认状态机、食物消费、指针断言仍然成立。
4. **跑真实浏览器**：`npm run probe:feeding` 或 `npm run probe:tap`，不要只看单元测试。
5. **看截图并记录**：检查鱼身重叠、穿玻璃、穿布景、姿态是否自然；把最终参数写进提交说明或本指南。

### 7.2 三个探针各自负责什么

| 命令 | 验证内容 | 适用改动 |
| --- | --- | --- |
| `npm test` | 状态转换、延迟、消费原子性、指针字符串 | 所有纯逻辑改动 |
| `npm run probe:feeding` | 真实 4 粒下沉、发现、聚集、争食、吃空散开、双态指针 | 投喂参数、速度、半径 |
| `npm run probe:tap` | 真实玻璃点击、四阶段受惊、单次响应、打断觅食后恢复 | 受惊参数、优先级 |
| `npm run probe:scape` | 三套造景下的渲染、避让、帧率与资源回收 | 改变运动或碰撞后必跑 |
| `npm run smoke` | 构建产物可被宿主桩加载、槽位和页面完整 | 改 UI、构建入口后必跑 |

探针会生成截图与 JSON 证据：

- `.screenshots/p4-feeding-gather.png`
- `.screenshots/p4-feeding-scatter.png`
- `.screenshots/p4-tap-flee.png`
- `.screenshots/p4-tap-settle.png`
- 对应 `p4-*-probe.json`

### 7.3 调试快照怎么读

在浏览器控制台执行：

```js
__DSH_AQUARIUM_TEST__.scene.snapshot()
```

`fishState` 中与行为有关的字段：

| 字段 | 含义 |
| --- | --- |
| `behavior` | 当前有效行为；受惊时优先显示 `alert/flee/settle`，否则显示觅食状态 |
| `feeding` | 觅食状态机的原始状态，便于区分“被受惊打断”与“根本没发现” |
| `reaction` | 受惊状态：`calm/alert/flee/settle` |
| `reactionIntensity` | 本次受惊强度，0.55～1 |
| `reactionTarget` | 当前逃逸目标；`calm` 时为 `null` |
| `startles` | 累计听到的敲击次数，用于确认“一次事件只响应一次” |
| `targetFoodId` | 当前占用的食物 id，`null` 表示未占用 |
| `foodDistance` | 与目标颗粒的距离 |
| `eaten` | 累计吃掉的颗粒数 |

常用排查组合：

```text
有食物但所有 fishState.feeding === 'cruise'
  → 检查 School.update 是否收到 feedingDirector

fishState.startles 每帧增加
  → 检查是否误按 taps.length 判断，而不是使用 WeakSet

受惊后 feeding 仍是 gather
  → 检查 startle.justTriggered 分支是否先调用了 feeding.interrupt()

吃完后立刻瞬移回原位
  → 检查 returnFrom / startleReturnTime 的回融分支是否被跳过

指针在水面上方没有变斜
  → 检查 pick() 是否真的返回 kind === 'water'，而不是 'glass'
```

## 8. 交付前的验收清单

以下每一项都应在**真实浏览器**里观察一次，而不是只看测试输出。

### 8.1 投喂

- [ ] 点击鱼食罐后指针立即变成倾斜小罐；移到水面上方变为更倾斜的倾倒姿态。
- [ ] 每次点击水面投入 4 粒（或你设定的 `LIMITS.batch`），颗粒可见地缓慢下沉。
- [ ] 近处鱼先发现、远处鱼稍后响应，所有鱼在约 1 秒内开始动作。
- [ ] 鱼不会全部挤在同一点，接近角度和泳层有可见差异。
- [ ] 同一颗粒只被吃掉一次；被抢的鱼会短暂悬停再换目标。
- [ ] 食物吃空后鱼分成松散小组散开，不永久堵在缸口。
- [ ] 散开结束与恢复巡游之间没有位置瞬移。
- [ ] 退出投喂或按 `Esc` 后，指针恢复默认，鱼不会继续追不存在的食物。

### 8.2 敲击受惊

- [ ] 单击玻璃只出现一次敲击光圈，不会连续触发多次受惊。
- [ ] 靠近敲击点的鱼先惊动，远处鱼稍慢；不是全缸同帧弹开。
- [ ] 鱼朝远离敲击点的方向逃跑，不穿玻璃、不穿石块、不穿沉木。
- [ ] 受惊过程中完整出现 `alert → flee → settle → calm`，没有卡在某一状态。
- [ ] 平复后回到正常巡游或继续觅食，位置不瞬移。
- [ ] 抢食中敲缸：鱼先放弃食物并逃离，平复后能重新发现剩余颗粒。
- [ ] 连续快速敲击仍受 300ms 节流保护，鱼不会无限加速或抖动。

### 8.3 指针

- [ ] 普通投喂角度和倾倒角度清晰可辨，差值约 30～40 度。
- [ ] 图标热点落在罐口，点击落点与视觉预期一致。
- [ ] 浅色、深色背景都能看清轮廓。
- [ ] 空白、玻璃、水面、拖动四种情况下光标状态正确。
- [ ] 触屏或没有 hover 的设备不会卡在自定义光标。

### 8.4 工程回归

```powershell
npm test
npm run build
npm run smoke
npm run probe:feeding
npm run probe:tap
npm run probe:scape
```

当前基线是 **57 项单元测试**全部通过、三套造景约 **60 FPS**、浏览器控制台无错误。新增测试后，基线数量应增加而不是减少；不要把旧的边界断言删掉来“让新参数通过”。

## 9. 已知边界与下一步

- 当前“投喂习惯”是代码内固定参数，定制页仅展示说明，尚未开放用户配置。若要开放，建议按 §4.5 的品种倍率方式做，而不是给每个参数单独加一个滑块。
- 食物只有一种类型和一种下沉速度分布；若要“挑食”，需要给食物增加 `kind`，并在 `FeedingBehavior.select()` 里按鱼的偏好重新评分。
- 受惊只由玻璃敲击触发；若要加入“突然开灯”“人影经过”等来源，应复用 `StartleBehavior.trigger()`，不要复制一套惊扰逻辑。
- 当前使用鼠标/触控板为主，触屏投喂和音效尚未纳入本阶段验收。
