# 鱼缸造景 3D 资产制作指南

> **已封装为 skill**：P5 起本指南的数据契约与验收判据收敛成 `aquarium-custom-core` + `aquarium-custom-scape`（`skills/aquarium-custom-scape/SKILL.md`），用户在定制页「水草与造景」一行点「做一个新的」即按本指南流程开工。本文继续作为原理与排查说明，流程以 skill 正文为准；区别与验收方法见 [P5 AI 定制工厂](../P5-AI定制工厂.md)。
>
> 适用范围：P3 内置造景（`substrate.*` + `plant.*` 成对登记），以及 P5 通过定制流程新增的 `scape.*` 资产（单条即一套布局，见 `scape.layout` / `scape.collision`）。
> 当前内置三套采用可复现的程序化几何；新增资产可以使用同样的数据契约，或在此契约外接 GLB。

## 1. 先明确交付物

一件合格造景不是单独一张图片或一个模型，而是一组可同时验收的内容：

1. 可见几何：石、木、草、苔藓或其他装饰。
2. 本地材质：PBR metallic-roughness；运行时不请求网络资源。
3. 清单记录：id、类别、版本、尺寸、锚点、来源与许可。
4. 占位数据：实体障碍使用 `solid`，植物使用 `soft`。
5. 预设数据：多个资产的空间布局、出气点、密度与高度上限。
6. 验证结果：边界、清单同步、切换释放、浅色／深色、投喂与鱼群回归。

当前实现入口：

- `src/scape-data.js`：三套布局、占位体、运行时单位换算与轻量中心避让。
- `src/scape.js`：石块、苔藓、沉木、折叠叶片和水摆着色器。
- `presets.json`：每个 `plant.*` / `substrate.*` 的正式登记。
- `scripts/sync-scape-manifest.mjs`：从布局同步清单，避免视觉与碰撞数据漂移。
- `tests/scape.test.mjs`：静态契约与边界回归。
- `scripts/scape-probe.mjs`：真实 WebGL 渲染、切换、投喂、水摆和资源回收判据。

## 2. 坐标、尺寸与单位

鱼缸局部坐标固定为 Y 向上，缸底中心为原点。已有缸体和水面契约不得因造景而改变。

| 项目 | 数值 / 规则 |
| --- | --- |
| 缸体外形 | 40 × 30 × 25 cm |
| 水体水平边界 | X = ±19.3 cm，Z = ±11.8 cm |
| 砂面参考 | Y ≈ 1.65 cm |
| 水面 | Y = 26.7 cm |
| 布局源数据 | 厘米，便于美术和清单阅读 |
| 运行时碰撞 | 米，与 Three.js 场景一致 |
| 朝向 | `+y` 向上；资产局部旋转不改变世界水面方向 |

`scape-data.js` 的布局以厘米书写；`getScapeCollision()` 统一除以 100 输出米。不要在一个文件里混用两种单位。

安全边界：

- 叶片最终顶点 X 限制在 ±19 cm，Z 限制在 ±11.5 cm。
- 内置高草叶尖不超过 Y=23 cm，留出水面和投喂通道。
- 石块与沉木不得伸出玻璃；沉木最高控制点连半径一起检查。
- 预设中心及前方保留主要观赏与投喂水域，不能用密植遮满缸体。

## 3. 预设与清单 id

配置字段是 `scapePresetId`，当前内置值：

| 预设 id | 名称 | 主要结构 |
| --- | --- | --- |
| `scape.moss` | 苔藓石景 | 高主石、次石、附着苔藓、低草 |
| `scape.jungle` | 水草丛林 | 后景高草、中景茎草／阔叶草、前景矮草 |
| `scape.driftwood` | 沉木疏林 | 分枝沉木、散石、稀疏草叶 |

每个预设拆成两条正式资产记录：

- `substrate.*`：石头与沉木，携带 `solid` 占位。
- `plant.*`：水草群，携带 `soft` 占位和水摆参数。

清单必填：`id`、`category`、`version`、`file`、`displayName`、`bounds`、`anchor`、`forward`、`params`、`collision`、`origin`、`license`、`author`、`source`。内置资产的 `origin` 必须为 `builtin`。

修改布局后执行：

```powershell
npm run scape:manifest
npm run test
```

不要手工只改 `presets.json` 的碰撞数字；下一次同步会以布局源数据为准。

## 4. 可见几何制作

### 4.1 石块

当前石块由细分二十面体合并顶点后做超椭球修形与多频确定性扰动，兼顾风化圆角和石块转折，再用平滑法线消除廉价的大块折面。材质使用高粗糙度、低环境反射、独立石材细颗粒凹凸和顶点色；石脚另有实例化碎砾衔接砂面。

新增石组时应遵守：

- 主石、次石、陪石有明确的大小关系，不做一排同尺寸圆球。
- 主石决定视觉重心，次石引导视线，陪石负责衔接砂面。
- 石块底部压入砂面少许，不能悬浮。
- `size` 是完整包围尺寸，不是半径；`center` 是占位中心。
- 旋转用于可见几何；P3 占位仍采用轴对齐盒，P4 若需要更精细可扩成凸包。

### 4.2 苔藓与水藻

苔藓是附着层，不是漂浮在石头上方的绿色粒子。当前采用两层结构：石体顶点色形成连续、斑驳的附着底色；再从真实石体顶点与法线采样，放置顺表面朝向的小型 InstancedMesh 簇，补充绒面起伏。

制作时要把苔藓实例放在可见石面附近；如果改了石体拓扑或缩放，必须重新检查附着位置。植物和苔藓颜色按 sRGB 输入再转线性，避免灯光下意外发白。省电模式只减少苔藓实例数，不移除整片生态层。

### 4.3 沉木

当前沉木使用 Catmull-Rom 中心线和逐控制点半径生成不对称锥形管状网格；横截面含纵向沟槽与轻微椭圆压缩，配合独立树皮凹凸贴图和末端封口。内置布局采用斜向主枝、横向根枝与不同高度的细侧枝，避免直立对称的“仙人掌”轮廓。每个分支包含：

```js
{
  points: [[11, 1.7, -2], [10.2, 6.2, -2.2], [11.8, 11.2, -3]],
  radii: [2.2, 1.75, 1.25]
}
```

`points` 与 `radii` 数量必须相同。主枝粗、侧枝细、末端收尖；根部可以加横向分枝增强抓地感。不要给所有分枝同样半径，也不要把沉木做成对称鹿角。

### 4.4 水草叶片

叶片是有杯状曲面、折叠中肋和微波叶缘的双面网格，不是十字交叉图片。当前四类参数：

| 类型 | 视觉用途 | 形态 |
| --- | --- | --- |
| `grass` | 后景高草 | 多段弯曲带状叶，叶尖收细并略下垂 |
| `carpet` | 前景地被 | 更低、更细、更外向弯曲的叶片 |
| `stem` | 中景茎草 | 独立细茎，3～5 个茎节生成对生叶，可选 `tint: 'red'` |
| `broadleaf` | 阔叶丛 | 七叶左右共根形成莲座，外层更短、更展开 |

每簇包含 `center`、`count`、`height`、`spread`、`width`，茎草可另含 `tint`。`count` 对茎草表示茎数，对其他类型表示叶片/叶序基数；实际三角面会高于叶片计数。密度和高度必须在数据层受上限约束，不能通过运行时每帧随机改变。

## 5. 水草随水摆动

水摆通过顶点着色器完成，不为每片叶子创建 JS 定时器或独立 Mesh。

每个顶点烘焙两项属性：

- `aFlex`：根部为 0，向叶尖按约 1.7 次幂增加。
- `aPhase`：每片叶子的独立相位，避免全缸同步摆动。

运行时只更新两个 uniform：

- `uPlantTime`：水摆时间。
- `uPlantStrength`：标准为 1，省电为 0.58。

顶点位移由主波和二次谐波组成；横向摆幅约 3.8 mm，纵深约 2.4 mm，并乘以 `aFlex`。因此根部不漂移，叶尖有延迟，叶片之间不会整齐划一。

省电模式把时间量化到 15 Hz，并降低摆幅；不要直接冻结全部植物，否则生态感会突然消失。

新增 GLB 植物若使用外部动画，仍要满足：根部固定、顶点不越界、每簇相位不同、资源可释放。不要同时对同一几何叠加两套顶点摆动。

## 6. 占位体契约

运行时每个占位体包含：

```js
{
  id: 'scape.jungle.rock.0',
  type: 'box',             // 或 cylinder
  kind: 'solid',           // 或 soft
  center: [-0.028, 0.045, -0.038],
  size: [0.064, 0.058, 0.052]
}
```

软占位使用 `radius` 和 `height`，不使用 `size`：

```js
{
  id: 'scape.jungle.plant.0', type: 'cylinder', kind: 'soft',
  center: [-0.152, 0.1165, -0.058], radius: 0.027, height: 0.2
}
```

职责划分：

- P3 输出稳定数据，并提供轻量中心点防穿模。
- P4 负责体素／采样点、最小通行宽度、路径查询和完整游动模式。
- 实体石木不可穿越；软草允许通过外围，但应避开密集中心。
- 占位只用于行为查询，不参与刚体物理，不要求与每片叶子精确一致。

场景通过 `scene.getCollision()` 和 `snapshot().collision` 暴露当前预设的米制数据。切换预设后旧数组随场景释放。

## 7. 出气点与投喂通道

每个预设定义独立 `airStone`。气石和全部气泡读取同一坐标，不能只移动气石而忘记气泡。

出气点应满足：

- 在砂面附近、在水体内；
- 不生成在玻璃外；
- 不被主石完全包住；
- 气泡到水面后消失，实例数量有硬上限。

切换预设后立即投喂是本阶段的强制回归。投喂模式使用真实射线交点，并优先选择水面命中，避免前侧玻璃抢先截获点击。

## 8. 性能与资源

当前实测规模（标准模式）：

| 预设 | 叶片 | 植物三角面 | 占位体 |
| --- | ---: | ---: | ---: |
| 苔藓石景 | 156（含茎草基数） | 约 10.4k | 13 |
| 水草丛林 | 291（含茎草基数） | 约 23.7k | 16 |
| 沉木疏林 | 133（含茎草基数） | 约 11.3k | 19 |

重复几何优先实例化；所有叶片合为一个带顶点属性的网格。新增资产要控制 draw call、贴图尺寸和三角面，不得通过每帧创建对象实现摆动。

所有几何、材质、贴图和实例必须注册到场景资源所有者。关闭或切换时统一 `dispose()`；异步鱼模型若在场景销毁后完成加载，也必须立即释放，不得重新挂回旧缸体。

## 9. 验收流程

```powershell
npm run scape:manifest
npm run test
npm run build
npm run smoke
npm run preview
npm run probe:scape
```

必须检查：

1. 三个 id 均可保存，未知 id 回退到 `scape.jungle`。
2. 石、木、草、出气点不越界；叶片有密度与高度上限。
3. 清单与运行时占位的数量、类型、中心坐标一致。
4. 水摆时间持续推进；省电模式降低摆幅。
5. 三种预设形状和空间可辨，不是仅换颜色。
6. 鱼中心不位于实体占位内部；投喂在切换后立即可用。
7. 浅色、深色、近景都可读；控制台无页面或 shader 错误。
8. 循环切换后 `renderer.info.memory` 回到同一水平，不持续增长。

预览与判据输出到 `.screenshots/p3-*.png` 和 `.screenshots/p3-probe.json`。这些是本地离线验证，不替代真实 DSH 宿主的最终安装验收。
