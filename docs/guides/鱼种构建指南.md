## 0. 先看全流程

一条新鱼从图片到入缸，固定经过九步：

```text
参考图筛选
  ↓
多视角 3D 生成（GLB + baseColor + normal）
  ↓
资产体检（面数 / 贴图 / 包围盒 / 连通性 / 扩展）
  ↓
形体与贴图清理（去背景色、去烘焙高光、调饱和度）
  ↓
坐标与尺度校准（体轴、背腹、侧向、原点）
  ↓
绑定（单网格分区权重 / 真实骨骼）
  ↓
材质与游动动效（身体波、鳍、行为）
  ↓
接入 species.js / scene.js / fish.js
  ↓
自动验收 + 缸内视觉回归
```

其中最容易出错的不是“生成模型”，而是后面四件事：

1. **资产坐标和项目约定不一致**，导致鱼头朝后、侧躺或分区权重全部错位；
2. **把“鳍”当成身体的一部分**，鱼游起来像一块会弯的板；
3. **贴图里已经烘焙了高光**，入缸后体侧发白、橙色发灰；
4. **只看了模型旋转图，没有看缸内小尺寸效果和连续动作**。

这份指南的每个阶段都给出“怎么判断做完了”，不要只凭“看起来还行”进入下一步。

## 1. 选择资产路线

不是所有鱼都适合同一种做法。先选路线，再开始建模，避免做完才发现动作方案不匹配。

| 路线 | 适合对象 | 外形来源 | 动作方式 | 当前项目入口 | 代价 |
| --- | --- | --- | --- | --- | --- |
| **A. 照片重建 + 分区权重** | 2 条以内的英雄鱼、外形识别度高的鱼 | 多视角照片生成单网格 | 顶点着色器虚拟骨骼 | `rig: 'clownfish'` 专用管线 | 单网格、单材质，鳍不能单独换材质 |
| **B. 程序化几何 + 图集** | 需要精确分件、鳍独立控制、可参数复现的鱼 | Python/Blender 参数化网格 | 独立 mesh + 顶点权重 | `scripts/clownfish/alternates/` 备选 | 外形容易有规则放样感 |
| **C. 手工低模 + 真实骨骼** | 群游鱼、动作复杂、需要鱼鳍独立骨骼 | Blender 建模/重拓扑 | glTF 骨骼动画 + `AnimationMixer` | `fish.js` 默认非小丑鱼路径 | 制作成本最高，需蒙皮与烘焙动画 |

### 怎么选

- **只有一条或两条、用户会凑近看、外形必须像参考图**：选 A。当前小丑鱼就是这条路线。
- **同屏数量多、外形可以概括、需要低面数**：选 C，或者 B 的低模版本。
- **需要精确的鳍片独立旋转、不同鳍不同透明材质**：选 B 或 C，不要硬把 A 的单网格拆成很多份。
- **已经有带 `Swim` 动画的 GLB**：直接走 C，不要再叠加顶点泳姿，否则会双倍变形。

### 项目里的默认选择

当前正式小丑鱼是 **A**：20,000 面单网格、1024² 颜色贴图、512² 法线贴图、五个鳍分区权重。程序化 7-mesh 版本保留为备选，不进入正式包。

新鱼如果没有特别要求，建议先做 A 的“外形验证版”，确认外形通过后，再决定是否需要为它升级成 B/C 的精细绑定。

## 2. 准备参考图

### 2.1 参考图不是越多越好，而是要“信息互补”

最低配置：

| 视角 | 用途 | 要求 |
| --- | --- | --- |
| 正侧面 | 体形、头身比、白带位置、鳍轮廓 | 鱼体完整，鳍尽量展开，不要被遮挡 |
| 3/4 斜前或斜后 | 头部体积、身体厚度、胸鳍着生点 | 眼睛、嘴、鳃盖清楚 |
| 正面或俯视 | 体宽、左右对称、背鳍走向 | 不要严重透视畸变 |
| 群体/环境图 | 真实体色、泳层、行为参考 | 只作参考，不直接喂给重建 |

理想情况给 3–8 张同一条鱼、光照一致、背景干净的照片。多视角重建最怕两件事：**同一部位在不同图里形状矛盾**，以及**背景里有第二条鱼/海葵/珊瑚干扰主体轮廓**。

### 2.2 参考图筛选标准

- 鱼体占画面足够大，至少长边 800–1000 px；
- 主体完整，不裁掉尾鳍、背鳍、腹鳍；
- 眼睛、嘴、鳃盖没有强反光遮挡；
- 白带与黑边能分辨，不是一整块过曝白；
- 背景与鱼体颜色差异明显，方便裁剪；
- 不要用两张不同个体拼成一套“多视角”，白带位置和体形会对不上。

### 2.3 预处理

1. **裁主体**：只保留一条鱼，去掉水印、文字、边框、其他鱼。
2. **去背景或统一背景**：优先干净纯色背景；如果去不干净，至少把主体外轮廓之外的内容裁掉。
3. **不要提前锐化或加滤镜**：生成模型会把滤镜当成真实纹理。
4. **保留一张未处理的原图**：后续颜色对照、贴图调色都要用。

项目示例：小丑鱼的参考原图保存在 `assets/p2-src/clownfish-reference.jpg`，但正式资产不直接采样它，贴图来自多视角重建结果。

### 2.4 参考图阶段验收

- [ ] 至少有一张完整侧面图；
- [ ] 至少有一张能看清头部体积和胸鳍着生点的斜视图；
- [ ] 所有图里白带数量、位置一致；
- [ ] 没有第二条鱼或大型造景遮挡主体；
- [ ] 已保存一份未处理原图。

## 3. 从图片生成 3D 网格

### 3.1 生成目标

生成阶段只解决“外形和表面颜色”，不要期待它直接给出可用的骨骼和游动动画。一个合格的重建结果应满足：

- 只有一个主体，没有珊瑚、海葵、底座、文字；
- 鱼体完整，鳍没有断裂、破洞、粘连；
- 头、嘴、眼睛、鳃盖的位置正确；
- 白带、黑边、鳍条等主要色块能辨认；
- 输出 GLB，贴图内嵌，最好同时带 normal map；
- 姿态接近中性游动姿态，身体不要大幅弯曲。

### 3.2 推荐参数

| 参数 | 英雄鱼（1–2 条） | 群游鱼（3 条以上） |
| --- | --- | --- |
| 面数 | 15,000–20,000 | 3,000–8,000 |
| 颜色贴图 | 1024×1024 | 512×512 或纯色材质 |
| 法线贴图 | 512×512 | 256×512 或省略 |
| 材质 | PBR，金属度 0 | 可用程序化鱼皮 |
| 姿态 | 中性、鳍展开 | 中性、左右对称 |
| 文件 | 单 GLB，贴图内嵌 | 单 GLB，尽量不要外部依赖 |

当前小丑鱼用了 20,000 面、1024² baseColor、512² normal。这个预算只适用于两条同屏的英雄鱼；群游鱼不要照抄。

### 3.3 提示词模板

给图生 3D 的提示词要同时约束“主体、视角、解剖、背景、输出”：

```text
A realistic <species name>, one single isolated fish only.
Match the reference images: <body shape>, <mouth/eye/head features>,
<exact stripe or spot pattern with positions>, <fin shapes and black margins>.
Natural anatomy, complete symmetrical 3D geometry, neutral swimming pose,
fins slightly spread, head pointing left and tail right.
No coral, no sea anemone, no rocks, no background, no pedestal, no text,
no second fish, no watermark.
```

对小丑鱼，关键约束是：

- 身体侧扁、钝吻、眼睛位于头部中上；
- 三条竖直白带：眼后、体中部、尾柄；
- 白带外有黑色包边，背鳍/臀鳍/尾鳍有黑色鳍缘；
- 胸鳍是扇形而不是贴片；
- 不要带海葵、珊瑚或第二条鱼。

### 3.4 多视角输入

如果服务支持多视角：

- 侧面图作为主视图，权重最高；
- 斜前/斜后图补充体积；
- 俯视图补充体宽和背鳍走向；
- 不要把有遮挡、有第二条鱼的图直接作为主视图；
- 如果不同视角主体不一致，宁可少给一张，也不要让模型“平均”出错误的头形。

### 3.5 生成后先做“三不判据”

先不要急着进项目，打开原始 GLB 或预览图检查：

1. **不混入**：没有背景、底座、第二条鱼；
2. **不残缺**：鳍、嘴、眼睛完整，没有破洞和融合；
3. **不畸形**：左右对称、头尾方向明确、没有多余肢体。

任一项失败，重新生成或换参考图，不要用后期材质掩盖几何问题。

### 3.6 产物落地

生成服务常返回临时下载链接，必须立刻保存：

- GLB 原始文件；
- 预览图；
- 如果有 OBJ/ZIP 包，只作为备份，不直接入项目；
- 颜色贴图、法线贴图可单独解出，便于调色和验收；
- 记录使用的参考图、提示词、面数和生成日期。

落盘顺序建议：

```text
.tmp/ 或 .probe/              本次生成的临时文件，可清理
  ↓ 选中的原始网格
scripts/<species>/source/     可复现的原始输入
  ↓ 调色 / 优化
assets/p2-src/<species>.glb   正式资产
```

不要让正式资产直接指向临时 URL，也不要把临时 GLB 当成唯一源文件。

## 4. 资产验收与清理

### 4.1 读取 GLB 的真实数据

不要只看体积和预览图。至少读一次：

- `meshes / nodes`：单网格还是独立分件；
- `triangles`：是否超过预算；
- `POSITION` 的 min/max：体轴、体高、体宽；
- `images`：颜色图和法线图是否内嵌、尺寸、MIME；
- `extensionsUsed`：是否有项目加载器不支持的扩展；
- 材质 `doubleSided`：单层鳍是否需要双面。

项目已有体检入口：

```powershell
node scripts/audit-fish.mjs
```

它会把 `assets/p2-src/*.glb` 的比例、面数、体积、贴图、动画和豁免情况写进 `scripts/fish-audit.json`。英雄鱼的面数/体积豁免必须写在 `scripts/audit-fish.mjs` 的 `OVERRIDES` 里，并写清理由，不能默默改上限。

### 4.2 文件命名与目录

推荐：

```text
assets/p2-src/<species>.glb                 正式 GLB
assets/p2-src/<species>-preview.png         静态封面
assets/p2-src/<species>-viewer.html         可旋转预览
scripts/<species>/source/                   原始重建网格
scripts/<species>/polish_*.py               可复现的贴图清理
docs/evidence/<species>-*.png               验收证据
docs/<species>-重制.md                      过程记录
```

小丑鱼当前对应：

```text
assets/p2-src/clownfish-ocellaris.glb
assets/p2-src/clownfish-ocellaris-preview.png
assets/p2-src/clownfish-ocellaris-viewer.html
scripts/clownfish/source/clownfish-photo-base.glb
scripts/clownfish/polish_photo.py
docs/P2-小丑鱼重制.md
```

### 4.3 资产清理原则

- **不要直接覆盖唯一源文件**。先把原始重建结果存进 `source/`，正式 GLB 由可复现脚本生成。
- **不要为了压体积盲目减面**。先看轮廓是否还成立，再决定减面或降贴图。
- **不要把贴图烘焙高光当成材质高光**。照片重建的颜色图里经常已经有白色反光，需要单独处理。
- **不要删除原始参考图**。它是配色和比例的最终依据。

### 4.4 生成阶段验收

- [ ] GLB 只有主体，无背景物体；
- [ ] 面数在预算内，或已登记英雄鱼豁免；
- [ ] 颜色贴图、法线贴图内嵌；
- [ ] 没有加载器不支持的扩展；
- [ ] 已保存原始重建文件和至少一张预览图。

## 5. 坐标、尺度与朝向

这一节决定鱼入缸后是“朝前游”还是“横着漂”。

### 5.1 资产局部坐标约定

项目内部按以下语义工作：

| 轴 | 含义 |
| --- | --- |
| X | 体长轴，吻端在 0，尾端在 1（局部归一化） |
| Y | 背腹轴，背为 +Y |
| Z | 左右体侧，z 的符号区分左右 |

“头在 0、尾在 1”是**资产局部坐标**，不等于最终世界朝向。最终入缸时，`normalize()` 会把最长轴转到 +X，再根据 `facing` 决定是否掉头。

### 5.2 `normalize()` 做了什么

`src/fish.js` 的 `normalize(root, targetLength, facing)`：

1. 用世界包围盒找最长轴；
2. 最长轴是 Y 就绕 Z 转 -90°，是 Z 就绕 Y 转 +90°；
3. `facing < 0` 时再转 180°，让头朝向 +X；
4. 按 `targetLength / 最长轴长度` 统一缩放；
5. 旋转、缩放后重新量包围盒，把几何中心移到原点。

所以资产自身的单位、Blender 的 100× 节点缩放都不重要，**不要相信 GLB 元数据里的尺寸**。

### 5.3 在 `species.js` 里声明朝向

```js
{
  targetLength: 0.062,   // 6.2 cm
  facing: -1,            // 资产头朝局部 -X，需要掉头
  axis: { along: 0, lift: 1, dorsal: 1 },
}
```

- `axis.along / lift / dorsal` 是给“程序化鱼皮/顶点泳姿”用的局部轴声明；
- 照片重建走专用分区管线时，`axis` 仍要填对，避免其它材质路径读错；
- 新鱼入缸前先看四角度：侧视头朝左/右、俯视背腹是否正确、正面左右是否对称。

### 5.4 体长与预算

当前缸体净空约 38.6 × 23.6 cm（以 `SPACE` 为准）：

- 单条大鱼 ≤ 8 cm；
- 群游鱼 ≤ 6.4 cm；
- 小丑鱼 `targetLength = 6.2 cm`。

新鱼的目标体长必须写进 `species.js`，不要依赖模型原始尺寸。

### 5.5 坐标阶段验收

- [ ] 四角度渲染中鱼不侧躺、不倒立；
- [ ] 头尾方向与游动方向一致；
- [ ] 原点在身体中心，不是尾尖或腹底；
- [ ] 体长与配置一致；
- [ ] 缸内没有一半身体穿出玻璃。

## 6. 绑定：单网格虚拟骨骼与真实骨骼

“绑定”不等于一定要有 Blender 骨骼。当前项目有两条可用的绑定路线：

- **单网格虚拟骨骼**：用顶点属性标明每个顶点属于身体还是哪片鳍，在顶点着色器里绕鳍根旋转。小丑鱼走这条。
- **真实骨骼**：在 Blender 里建脊柱与鳍骨，蒙皮后烘焙 `Swim` 动画，走项目的 glTF 动画路径。

两条路线只能选一条，不能把真实骨骼动画和 `rig: 'clownfish'` 的顶点泳姿同时打开。

### 6.1 路线 A：单网格虚拟骨骼

#### 要解决什么问题

照片重建通常输出一整张连通网格。你没法像独立 mesh 那样：

```js
// 这类判断对单网格无效
if (node.name.includes('pectoral')) { ... }
```

所以要换一种“骨骼”表达：

- 用 `aBody.x` 表示顶点沿体轴的位置；
- 用 `aBody.y` 表示顶点在鳍上的“鳍根 → 鳍缘”权重；
- 用 `aRegion` 表示顶点属于身体、背鳍、臀鳍、尾鳍、胸鳍还是腹鳍；
- 用固定的三维枢轴（pivot）表示肩关节、腹鳍根、尾柄。

这些属性在加载时烘焙一次，之后每帧只更新 uniform 和顶点着色器。

#### 第一步：确认几何是单连通网格

用项目里的连通性检查：

```powershell
python scripts/clownfish/analyze_components.py assets/p2-src/clownfish-ocellaris.glb
```

如果输出 `components 1`，说明所有鳍和身体是连在一起的。这种资产要按空间分区，不要试图按 mesh 名称分件。

如果输出多个 component，可以检查是否能按连通块拆成“身体、左胸鳍、右胸鳍、尾鳍”，再走独立 mesh 路线。

#### 第二步：把包围盒归一化成解剖坐标

设总包围盒：

```text
minX, maxX
minY, maxY
minZ, maxZ

u  = (x - minX) / (maxX - minX)          // 0 吻端 → 1 尾端
yn = (y - centerY) / ((maxY - minY)/2)   // -1 腹 → +1 背
zn = (z - centerZ) / ((maxZ - minZ)/2)   // -1 左 → +1 右
```

注意：这里用的是**含鳍的整体包围盒**。它的好处是分区阈值可以直接按比例表达，不依赖模型原始单位；坏处是体形不同的鱼阈值不能照抄。

#### 第三步：按区域烘焙 `aRegion`

小丑鱼当前使用的判据如下，顺序不能乱，先匹配尾鳍，再匹配背/腹/胸鳍：

| 区域 | 条件（归一化坐标） | 说明 |
| --- | --- | --- |
| 尾鳍 `CAUDAL` | `u > 0.78` | 从尾柄后缘到尾鳍外缘 |
| 背鳍 `DORSAL` | `0.13 < u < 0.75 && yn > 0.52 && abs(zn) < 0.42` | 只取背中线附近的薄膜 |
| 腹鳍 `PELVIC` | `0.18 < u < 0.47 && yn < -0.62 && abs(zn) < 0.50` | 腹部前段、靠体侧中线的鳍 |
| 臀鳍 `ANAL` | `0.44 < u < 0.78 && yn < -0.62 && abs(zn) < 0.38` | 腹部后段 |
| 胸鳍 `PECTORAL` | `0.18 < u < 0.47 && abs(zn) > 0.58 && -0.52 < yn < 0.34` | 体侧外伸的扇形鳍 |
| 身体 `BODY` | 其余 | 包含头、躯干、眼窝区域 |

当前 11,937 个顶点分区结果：

```text
身体 5,808
背鳍 1,654
臀鳍   537
尾鳍 1,181
胸鳍 1,950
腹鳍   807
```

这不是“通用鱼类分区表”，而是一条 20k 小丑鱼的实际标定结果。新鱼必须重新做区域着色检查。

#### 第四步：烘焙鳍根 → 鳍缘权重

对每片鳍，用解剖范围算 `tip`（0 = 鳍根，1 = 鳍缘）：

```text
背鳍: tip = clamp((yn - 0.52) / 0.48, 0, 1)
腹鳍: tip = clamp((-yn - 0.62) / 0.38, 0, 1)
臀鳍: tip = clamp((-yn - 0.62) / 0.38, 0, 1)
尾鳍: tip = clamp((u - 0.78) / 0.22, 0, 1)
胸鳍: tip = clamp((abs(zn) - 0.58) / 0.42, 0, 1)
```

然后写入：

```text
aBody = vec3(u, tip, 0)
aRegion = 区域编号
```

对于独立分件资产，`aBody.y` 可以直接用该鳍的 UV v 坐标（如程序化备选版）；对单网格照片资产，必须用上面的解析权重。

#### 第五步：为什么鳍根权重必须为 0

如果胸鳍的所有顶点都按同一个角度绕肩关节旋转，鳍根和身体连接处会被拉开，形成一条裂缝或尖刺。

当前 `VERT_BEND` 里的处理：

```glsl
float finRoot = smoothstep(0.0, 0.26, fishV);
float rowA = sin(uRowPhase) * 0.30 * uRowAmp * fishSide * finRoot;
float rowB = sin(uRowPhase + 1.35) * 0.17 * uRowAmp * fishSide * finRoot;
```

- 鳍根 `fishV≈0`：旋转量为 0，跟身体完全贴合；
- 鳍中段：逐渐开始划水；
- 鳍缘：达到最大摆幅。

尾鳍、背鳍、臀鳍的 flutter 也乘 `pow(fishV, 2.0)` 或 `pow(fishV, 1.55)`，同样是“根部不动、边缘最大”。

#### 第六步：找枢轴（pivot）

当前小丑鱼的虚拟关节：

```js
uPectoralPivot = (0.305, -0.005, 0.060)  // 肩关节，z 由左右符号取反
uPelvicPivot   = (0.320, -0.185, 0.025)  // 腹鳍根，z 由左右符号取反
```

这些数值是**资产局部坐标**，不是世界坐标。换鱼种时按以下方法找：

1. 在分件调试图里找到胸鳍与身体连接的中心；
2. 读取该点的 x / y / z；
3. 把数值写进 `clownfishMaterial()` 的 uniforms；
4. 旋转幅度先设为 0.2，检查鳍根是否围绕正确的点转；
5. 再恢复 0.30 / 0.17 等正式幅度。

对左右成对的鳍，枢轴的 z 要乘以 `fishSide`（顶点 z 的符号），不要写死一个方向。

#### 第七步：分区着色验收

`npm run lab:clown:fins` 会按 `aRegion` 给顶点上色：

```text
深绿 = 身体
红   = 背鳍
橙   = 臀鳍
亮绿 = 尾鳍
蓝   = 胸鳍
粉   = 腹鳍
```

验收标准：

- 每个颜色都落在真实鳍面上；
- 身体没有蓝色/粉色斑块；
- 鳍根没有大块身体颜色混入；
- 尾鳍与尾柄的交界干净；
- 左右胸鳍对称。

如果颜色边界错了，先改阈值，不要先改动作幅度。分区错了，动作一定错。

#### 第八步：单网格绑定的限制

- 所有鳍共用一张贴图和一套材质，不能给胸鳍单独做半透明；
- 不能像真实骨骼那样做口腔开合、鳃盖独立运动；
- 极端弯折时可能出现局部拉伸，幅度要限制；
- 真正需要独立鳍骨时，应该重拓扑或重新建模，不要无限加分区。

### 6.2 路线 C：真实骨骼绑定

#### 适合什么时候用

- 需要长期复用的鱼种；
- 需要独立控制背鳍、胸鳍、腹鳍、下颌；
- 群游鱼要做多套动作（巡游、冲刺、转向、觅食）；
- 已经有 Blender 制作能力，愿意维护骨骼与动画。

#### 骨骼建议

一条典型的鱼骨架：

```text
Root
└─ Spine_01
   ├─ Spine_02
   │  └─ Spine_03
   │     └─ Caudal
   ├─ Pectoral_L
   ├─ Pectoral_R
   ├─ Pelvic_L
   ├─ Pelvic_R
   └─ Jaw（可选）
```

背鳍/臀鳍可以加两根辅助骨，但不要给每根鳍条都建骨，蒙皮和动画成本会迅速上升。

#### Blender 操作顺序（参考）

1. **导入与清理**：导入 GLB，删除灯光/相机/空物体；确认只有鱼主体和需要的鳍。
2. **统一朝向**：让头朝 -Y 或 +X（按项目约定，最终由 `normalize()` 处理），背朝上；应用 `Scale` 和 `Rotation`，不要留未应用变换。
3. **重拓扑（照片网格必做）**：用 Quad Remesher、Shrinkwrap 或手工重拓扑，把 20k 三角面整理成以四边面为主的低模；保留嘴、眼窝、鳃盖、鳍根的关键环线。
4. **建骨架**：在原点新建 Armature，按上面的层级建脊柱、尾骨、左右胸鳍/腹鳍骨。骨骼要落在体腔中心，不要浮在体表。
5. **设置骨骼滚转**：鱼是左右摆尾，脊柱骨的局部轴要统一，避免动画时出现扭转；必要时用 `Recalculate Roll`。
6. **自动权重打底**：选中网格，再选骨架，`Parent → Armature Deform → With Automatic Weights`。自动权重只作为底稿，不能直接交付。
7. **手工修权重**：在 Weight Paint 里修三个地方——头部（保持稳定）、鳍根（与身体平滑过渡）、尾柄（不要硬折）。用 `Blur` 平滑边界，用 `Normalize All` 清理未归一化权重。
8. **验证极限姿态**：在 Pose Mode 把尾部左右各摆到最大幅度，检查鳍根、鳃盖、嘴角是否被拉裂；有问题回权重，不要靠动画幅度掩盖。
9. **烘焙动画**：在 Pose Mode 做 `Swim` 循环，30 fps、1.2–2.0 s；尾骨滞后 20%–30%，胸鳍左右反相；根骨不加位移。
10. **导出 GLB**：只选主体和骨架，`File → Export → glTF 2.0`，格式 `GLB`，勾选 Skinning、Animations，贴图内嵌，应用变换。

绑定要求：

- bind pose 是中性游动姿态，身体不要预先弯曲；
- 鳍骨枢轴放在鳍根，而不是鳍尖；
- 身体脊柱权重沿体轴平滑过渡，头部权重稳定；
- 每片鳍的根部和身体有 1–2 圈共享权重，避免硬折；
- 每个顶点最多 4 个骨骼影响，权重归一化；
- 不要把尾鳍完全刚性绑定到尾柄，留一点滞后。

#### glTF 导出

- 只导出鱼主体、骨骼和需要的动画，不导出灯光、相机、参考图；
- 单位与朝向统一，应用缩放和旋转；
- 动画命名为 `Swim` 或 `Swim_Cruise`，项目会优先匹配 `/swim|normal|idle/i`；
- 动画必须循环，首尾姿势一致；
- **根骨不能有位移通道**，否则鱼会被动画带出缸；
- 动画时长建议 1.2–2.0 s，30 fps 烘焙；
- 导出 GLB，贴图内嵌，检查 `animations`、`skins`、`nodes` 是否完整。

#### 项目中的加载方式

非 `rig: 'clownfish'` 的鱼会：

1. 使用 `GLTFLoader` 加载；
2. 用 `AnimationMixer` 播放 `Swim`；
3. 用 `SkeletonUtils.clone()` 克隆每条鱼，避免整群共用一套骨骼；
4. 用 `normalize()` 做尺度、朝向和居中。

如果你把一条真实骨骼鱼误设为 `rig: 'clownfish'`，会出现：

- 骨骼动画仍在播放；
- 顶点着色器又叠了一层脊柱弯曲；
- 鱼体被双重变形，鳍根错位。

所以：**真实骨骼资产不要走小丑鱼专用 rig。**

#### 真实骨骼验收

- [ ] GLB 含 `skins` 和至少一个 `Swim` 动画；
- [ ] 动画根骨无平移；
- [ ] 循环点无跳变；
- [ ] `SkeletonUtils.clone()` 后每条鱼动作相位可独立；
- [ ] 关闭顶点泳姿，仍然能正常游；
- [ ] 鱼鳍没有被蒙皮拉成薄片或穿插身体。

### 6.3 两条绑定路线的选择建议

| 需求 | 推荐 |
| --- | --- |
| 2 条以内、照片级外形、只做巡游/悬停 | 单网格虚拟骨骼 |
| 群游 5 条以上、低模、需要多套动作 | 真实骨骼 |
| 需要单独控制鳍材质/透明度 | 分件 + 虚拟骨骼，或真实骨骼 |
| 需要嘴部开合、鳃盖运动 | 真实骨骼 |
| 没有 Blender、只有图片 | 单网格虚拟骨骼 |

## 7. 材质与贴图

### 7.1 先分清两种“高光”

鱼体上看到的亮部可能来自两个完全不同的来源：

1. **真实材质高光**：由灯光、环境贴图、粗糙度、清漆产生，会随视角变化；
2. **照片烘焙高光**：照片重建把拍摄时的反光直接画进了 baseColor，永远不会随视角变化。

第二种是照片鱼入缸后“发白、发粉、像塑料”的主要原因。不能只靠调 `roughness` 解决，必须先从贴图或片元着色器里压掉。

### 7.2 颜色贴图清理

对小丑鱼，原贴图里大量橙色像素被照片高光冲成淡粉。处理原则：

- 只处理**暖色像素**：`r` 是最大通道且 `r - g >= 6`；
- 排除白带：白带近似 `r≈g≈b`，不满足暖色条件；
- 排除黑边：亮度低于阈值不处理；
- 在 HSV 空间提高饱和度，保持色相在橙色范围：
  - `h ∈ [0.015, 0.13]`（约 5°–47°）；
  - `s = max(s, 0.60)`，上限 0.84；
  - `v = max(v, 0.66)`，避免把暗部提灰；
- 重新编码 JPEG 时质量不要低于 90，避免白带边缘出现彩色块。

项目实现：`scripts/clownfish/polish_photo.py`。

```powershell
npm run asset:clown:photo
```

这个脚本从 `scripts/clownfish/source/clownfish-photo-base.glb` 读取原始重建资产，输出正式 GLB。它不会动白带和黑边。

### 7.3 缸内第二次颜色校正

照片贴图的橙色仍然可能偏灰，片元着色器再做一次“只压暖色”的校正：

```glsl
float clownChroma = max(max(r, g), b) - min(min(r, g), b);
float clownOrange = smoothstep(0.06, 0.28, r - g);
float clownPaleOrange = smoothstep(0.018, 0.11, r - g)
                      * (1.0 - smoothstep(0.10, 0.27, clownChroma));
float clownWarm = max(clownOrange, clownPaleOrange * 0.82);
diffuseColor.rgb *= mix(vec3(1.0), vec3(0.96, 0.66, 0.46), clownWarm);
```

要点：

- `clownOrange` 处理正常饱和的橙色；
- `clownPaleOrange` 专门处理“色相还是橙、但被冲淡”的粉色高光；
- 白带因为 `r≈g≈b`，`r-g` 很小，不会被处理；
- 黑边亮度低，也不会被当成橙色；
- 不能把整个材质乘一个橙色，否则白带会变黄。

最后压一次中性亮面：

```glsl
float clownLuma = dot(diffuseColor.rgb, vec3(0.2126, 0.7152, 0.0722));
float clownNeutral = 1.0 - smoothstep(0.045, 0.18, clownChroma);
diffuseColor.rgb *= 1.0 - 0.10 * clownNeutral * smoothstep(0.62, 0.92, clownLuma);
```

它会把白带和烘焙高光一起压 10%，让它们不再像发光贴纸。

### 7.4 当前小丑鱼材质参数

照片重建版是单网格、单材质，参数写在 `src/clownfish.js`：

| 参数 | 值 | 理由 |
| --- | --- | --- |
| `normalScale` | 0.70 | 照片法线细节强，缸内小尺寸容易起噪点 |
| `roughness` | 0.64 | 压掉照片贴图的塑料感 |
| `metalness` | 0 | 鱼皮是介质膜，不是金属 |
| `clearcoat` | 0.045 | 只保留很薄的湿皮反光 |
| `clearcoatRoughness` | 0.62 | 清漆高光要散，不要成镜面 |
| `envMapIntensity` | 0.16 | 缸内 PMREM 很亮，环境反射必须压低 |
| `side` | `DoubleSide` | 单网格的鳍是开放面，单面会从侧面消失 |
| `ior` | 1.4 | 接近水的折射率，避免像塑料球 |

如果是独立分件的程序化鱼，可以沿用同一套风格，但鳍和眼睛可以单独设置：

- 鳍：`roughness 0.56`、`clearcoat 0.10`、可透明；
- 眼睛：`roughness 0.05`、`clearcoat 1`、深色；
- 身体：`roughness 0.54`、`clearcoat 0.12`。

原则：**同一缸里的所有鱼必须在同一套灯光和色调映射下比较**，不要在调试台加一盏缸里没有的补光灯。

### 7.5 法线贴图

照片重建一般会带 normal map。使用注意：

- 512² 对 6 cm 的鱼足够；
- 法线贴图不要用 sRGB，GLTFLoader 会自动处理；
- `normalScale` 不要超过 1.0，照片法线常带噪点；
- 如果鳍条细节在近景里变成黑色颗粒，先降 `normalScale`，不要先加 roughness；
- 法线贴图转 JPEG 可以省体积，但要注意压缩块；能用 PNG 就用 PNG。

### 7.6 贴图预算

| 资产 | baseColor | normal | 备注 |
| --- | --- | --- | --- |
| 英雄鱼 | 1024² | 512² | 2 条以内 |
| 群游鱼 | 512² | 256² 或无 | 优先纯色/程序化 |
| 静态装饰鱼 | 512² | 无 | 不值得为它加 normal |

### 7.7 没有可用贴图时：程序化鱼皮

如果参考资产没有 UV，或只有 32×32 占位图，不要在低模上硬贴一张模糊照片；走 `src/fish.js` 的
`skinMaterial()`，在物体空间用 `aBody` 生成表面。四层缺一不可：

| 层 | 作用 | 参数入口 |
| --- | --- | --- |
| 反荫蔽 | 背深腹浅，建立圆柱体积 | `back` / `belly` |
| 鳞片 | 交错椭圆鳞，边缘压暗、高光偏硬 | `scaleGrid` / `scaleStrength` |
| 侧线 | 体侧一条纵向亮带，识别物种 | `lateral` / `accent` |
| 虹彩 | 掠射角偏冷，模拟鳞膜 | `iridescence` |

调用方式（大致）：

```js
const skin = skinMaterial(
  {
    back: 0x24363d,
    belly: 0x94a5a2,
    accent: 0xc9dcd8,
    scaleGrid: [52, 14],
    scaleStrength: 0.11,
    lateral: 0.9,
    iridescence: 0.45,
    roughness: 0.48,
    metalness: 0.1,
    envIntensity: 0.24,
    axis: SPECIES.newfish.axis,
  },
  { min: bounds.min, size: bounds.size },
  0,
);
```

关键经验：

- 反荫蔽的背深腹浅是最有效的“真鱼感”来源，先把这条调对，再调鳞片；
- 鳞片只压 2–3% 明度，压过头会像蛇皮；
- 侧线不能太宽，窄亮带比宽色块更像鱼；
- 低模上 `roughness` 不要低于 0.38，否则整条鱼会糊成高光；
- 程序化鱼皮必须用缸内同一套光照测试，否则颜色会偏。

### 7.8 透明与双面

- 薄鳍是单层面片时，必须 `DoubleSide`；
- 半透明鳍要 `transparent: true`、`depthWrite: false`，否则会出现排序错误；
- 照片重建的单网格不要给整条鱼开透明，只给真正需要透明的鳍；
- 阴影建议只让身体投影，薄鳍投影会变成黑块。

### 7.9 材质验收

- [ ] 白带仍是中性白，不发黄、不发蓝；
- [ ] 黑色鳍缘不发灰；
- [ ] 橙色在缸内灯光下仍是橙，不是暗红或粉色；
- [ ] 体侧没有大块固定不动的白色高光；
- [ ] 鳍从两侧看都不消失；
- [ ] 近景没有明显 JPEG 色带或法线噪点；
- [ ] 与参考照片并排看，色相和明度关系一致。

## 8. 动效：身体、鳍与行为

### 8.1 分三层，不要一条正弦走天下

合格的鱼游动至少分三层：

1. **身体行波**：头部几乎不动，波动向尾部逐渐增强；
2. **鳍的局部动作**：尾鳍滞后、背/臀鳍轻摆、胸鳍独立划水；
3. **行为层**：悬停、巡游、冲刺、转向侧倾、速度与频率耦合。

如果三层共用一个相位，整条鱼会像一块同步摆动的板。

### 8.2 身体：脊柱行进波

当前单网格顶点着色器使用：

```glsl
float swimEnvelope(float u) {
  float e = smoothstep(0.04, 1.0, u);
  return e * e;
}

float swimOffset(float u) {
  float ph = (uSwimTime + uSwimPhase) - u * 2.35;
  float wave = sin(ph) + 0.16 * sin(2.0 * ph + 0.7);
  return 0.135 * uSwimAmp * swimEnvelope(u) * wave;
}
```

然后求局部切线角，把截面和法线一起旋转：

```glsl
float theta = atan((swimOffset(ub) - swimOffset(ua)) / max(ub - ua, 1e-4));
fishP.x += fishP.z * sin(theta);
fishP.z = fishP.z * cos(theta) + swimOffset(fishU);
fishN = rotateY(fishN, theta);
```

关键：

- **只做 z 平移不够**，截面必须跟着切线转，否则是“纸板被推着走”；
- 头部 `u≈0` 时包络接近 0，头不会左右甩；
- 尾部 `u≈1` 时振幅最大；
- 二次谐波让波形不对称，避免木偶感。

### 8.3 尾鳍：滞后与弹性

尾鳍不能和尾柄同相位：

```glsl
float lag = (uSwimTime + uSwimPhase) - 2.2 - fishV * 2.6;
flutter = 0.062 * uSwimAmp * pow(fishV, 1.55) * sin(lag);
```

含义：

- 尾柄先动，尾鳍后动；
- 越靠鳍缘，摆幅越大；
- `pow(fishV, 1.55)` 保证鳍根不撕裂；
- 再给一点垂直方向弹性，避免像刚性扇子。

### 8.4 背鳍与臀鳍

```glsl
dorsal: 0.010 * amp * pow(tip, 2) * sin(time + phase + 1.8 - u * 3.0)
anal:   0.008 * amp * pow(tip, 2) * sin(time + phase + 2.4 - u * 2.4)
```

它们不需要大摆幅，只要让鳍缘在身体弯曲时有一点滞后，读者就会觉得“鳍是软的”。

### 8.5 胸鳍：独立划水

胸鳍是悬停时的主要推进器，不能跟着身体一起摆。当前实现：

```glsl
float finRoot = smoothstep(0.0, 0.26, fishV);
float rowA = sin(uRowPhase) * 0.30 * uRowAmp * fishSide * finRoot;
float rowB = sin(uRowPhase + 1.35) * 0.17 * uRowAmp * fishSide * finRoot;
```

- 两个轴相差约 90°，形成“划桨”而不是“扇风”；
- 左右用 `fishSide` 反相；
- 鳍根权重为 0，接缝不裂；
- 悬停时 `rowAmp` 高、频率约 2 Hz；巡游时幅度下降，频率也下降。

### 8.6 行为层：`ClownfishPilot`

当前小丑鱼不是沿椭圆路径匀速走，而是状态机 + 限加速度：

| 状态 | 时长 | 速度 | 动作 |
| --- | --- | --- | --- |
| `hover` | 2.2–4.8 s | 0.02 m/s 量级 | 胸鳍划水，尾拍很小 |
| `cruise` | 1.6–3.8 s | 0.065 m/s | 身体波明显，尾拍变快 |
| `dart` | 0.32–0.54 s | 0.20 m/s | 短冲刺，快速转向 |

行为细节：

- 悬停目标点沿领地缓慢绕圈，不是钉死；
- 速度用一阶滞后逼近，不会瞬移；
- 偏航角限速转向，转弯时 `roll ∝ -yawRate`；
- 尾拍频率随速度从约 2.1 Hz 升到 7.7 Hz；
- 与同种鱼保持软斥力，与缸壁/水面保持软边距；
- 冲刺结束后回 `hover`，形成“停—走—停”的节奏。

### 8.7 如果是真实骨骼动画

- 在 Blender 里烘焙 `Swim`，而不是在 Three.js 里再写一层顶点波；
- 尾骨相位比脊柱晚 20%–30% 周期；
- 左右胸鳍反相；
- 根骨零位移；
- 首尾帧一致；
- 导出后用 GLTFLoader 读回，确认 `animations[0].name` 与项目匹配；
- 群游时每条鱼用不同 `action.time` 起始偏移。

### 8.8 动效验收

- [ ] 头部稳定，不左右甩；
- [ ] 身体波动从 0 逐渐增强到尾柄；
- [ ] 尾鳍比尾柄晚半拍；
- [ ] 左右胸鳍反相，悬停时持续划水；
- [ ] 背鳍/臀鳍有轻微滞后，不是刚性板；
- [ ] 鳍根无裂缝、无尖刺；
- [ ] 转弯有侧倾，不瞬间掉头；
- [ ] 冲刺不穿缸、不贴玻璃硬拐；
- [ ] 连续帧联系表里没有“同一姿势卡住”。

### 9.1 需要改的文件

| 文件 | 作用 |

| `src/species.js` | 物种参数：体长、数量、朝向、行为、rig |

### 9.2 配置模板

```js
export const SPECIES = {
  // ...
  newfish: {
    id: 'newfish',
    name: '新鱼',
    targetLength: 0.062,
    count: 2,
    facing: -1,
    axis: { along: 0, lift: 1, dorsal: 1 },
    rig: 'newfish',          // 只有自定义管线才需要
    cruise: 0.56,
    heightBase: 0.095,
    heightStep: 0.052,
    space: SPACE,
  },
};
```

如果不使用专用 rig，删掉 `rig` 字段，走默认的 GLB / 骨骼路径。

### 9.3 加载模板

```js
import newFishGlb from '../assets/p2-src/newfish.glb';
import { School } from './fish.js';
import { SPECIES } from './species.js';

const schools = [
  { school: new School(tank, SPECIES.newfish, { seed: 3.14 }), source: newFishGlb, ready: false },
];
```

异步加载时保持“单种失败不拖累其他鱼”的原则：

```js
entry.school.load(entry.source)
  .then(() => { /* ready / compile / callback */ })
  .catch(error => { console.warn('[aquarium] fish load failed:', error); });
```

### 9.4 新增英雄鱼 rig 的注意事项

当前 `School.load()` 里只认：

```js
const isClown = this.species.rig === 'clownfish';
```

增加第二种英雄鱼时，不要直接把所有鱼都改成 `rig: 'clownfish'`。推荐做法：

1. 复制 `src/clownfish.js` 为 `src/<species>.js`；
2. 修改内的分类阈值、枢轴、材质和 `Pilot`；
3. 在 `fish.js` 增加一个按 `species.rig` 分派的适配层，例如：

```js
const customRig = this.species.rig && this.species.rig !== 'none';
if (customRig) {
  // 根据 rig 名称选择对应的 bake / material / pilot
}
```

4. 不要让两个自定义 rig 同时写同一套顶点属性；
5. 如果只是普通骨骼鱼，直接走默认 `GLTFLoader + AnimationMixer`，不要接自定义泳姿。

当第二种英雄鱼出现时，建议把 `clownfish.js` 里的公共“区域权重 + 材质 + Pilot”拆成 `src/rigs/` 适配器，而不是复制第三份。

### 9.5 克隆与资源释放

- 骨骼鱼必须用 `SkeletonUtils.clone()`，普通 `clone()` 会共用骨骼；
- 单网格自定义 rig 可以共享几何，但每条鱼要有自己的 `state` 和 `pilot`；
- 材质如果每条鱼独立，动画结束后要 `dispose()`；
- 贴图要复用，不要每条鱼各自解一张 1024 贴图；
- 纹理与几何的释放逻辑写在 `School.dispose()`。

### 9.6 接入验收

- [ ] 页面能加载，控制台无 `GLTFLoader` 报错；
- [ ] 鱼数量正确，全部在水体内；
- [ ] 每条鱼动作相位不同，不是整群同步；
- [ ] 单条失败不影响其它鱼；
- [ ] 刷新/切换主题后不残留旧鱼；
- [ ] 销毁场景后 WebGL 资源能释放。

### 10.4 图像证据要拍什么

最少四张：

1. **资产三行图**：四角度 / 四泳姿相位 / 四近景；
2. **泳姿胶片**：一个完整尾拍周期，侧视 + 3/4 + 俯视；
3. **缸内近景**：zoom 2.2×，看真实灯光下的颜色和比例；
4. **缸内连续帧**：至少 8 帧、0.35 s 间隔，看行为节奏。

有参考照片时再加一张左右并排对照图，不要用“模型旋转后某一帧”代替标准侧视对照。

### 10.5 自动化判据

能程序化验证的，不要靠肉眼：

- 鱼数量 = 配置数量；
- 所有鱼 `in-water`；
- 1.2 s 位移在合理区间；
- y 泳层在水深范围内；
- 帧率不低于目标；
- 控制台没有 error；
- 资产面数/体积在预算内；
- 分区顶点数非零，且各鳍比例合理；
- 不同泳姿相位的截图存在像素差异（证明顶点真的在变，不是只移动了位置）。

### 10.6 视觉判据

- 轮廓像参考鱼，不像通用鱼；
- 头部体积成立，不是圆柱；
- 白带数量、位置、宽窄正确；
- 黑边连续，不是脏灰；
- 胸鳍/尾鳍/背鳍没有缺口或穿插；
- 在缸内 100–200 px 尺寸下仍能读出物种；
- 与红绿灯同屏时比例不突兀；
- 游动时头部稳定、尾部有波、鳍有滞后。

一条鱼只有同时满足以下条件，才算“可入缸”：

- [ ] 资产体检 PASS；
- [ ] 四角度、四相位、尾拍周期都通过；

## 11. 常见问题与修复

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 尾鳍外缘发蓝 | 参考图蓝底被投影进贴图 | 只中和强蓝像素，不要全局去蓝；保留橙与白 |
| 体侧有固定白斑 | 照片高光烘焙进 baseColor | 贴图只对暖色像素提饱和；片元压中性亮面 |
| 橙色发灰/发粉 | 贴图饱和度低 + 缸内高光 | 先用 `polish_photo.py`，再调 shader 暖色权重 |
| 橙色发暗红 | 橙色 tint 过强 | 提高 tint 的 G/B，保持 R 接近 1；不要只压 R |
| 白带发黄 | 全局橙色乘法 | 只在 `r-g` 大的像素上做橙色校正 |
| 黑边发灰 | 贴图黑不够黑 + 清漆太强 | 压黑像素、降 clearcoat、提高 roughness |
| 鳍从侧面消失 | 单层面片 + FrontSide | `DoubleSide`，并检查法线朝向 |
| 鳍根裂缝/尖刺 | 鳍根旋转权重不是 0 | 用 `smoothstep(0, 0.26, tip)`，根部不转 |
| 胸鳍不划水 | 单网格没有识别出胸鳍 | 看 `lab:clown:fins` 的蓝色区域，修分区阈值 |
| 整条鱼像纸板 | 只平移顶点，没有旋转截面 | 用切线角同时旋转位置和法线 |
| 头部左右甩 | 波包络在头部不为 0 | `smoothstep(0.04, 1.0, u)^2` |
| 尾鳍和尾柄同步 | 尾鳍没有相位滞后 | 尾鳍加 2.2 rad 滞后 + tip 幅度 |
| 鱼侧躺/倒立 | 资产坐标与 `axis` 不一致 | 四角度检查，修 normalize/facing |
| 鱼头朝后游 | `facing` 与资产头端不一致 | 改 `species.facing`，不要用旋转动画硬掰 |
| 动作是双份的 | 骨骼动画 + 自定义顶点泳姿同时开启 | 真实骨骼鱼不要设 `rig: 'clownfish'` |
| 整群同步摆尾 | 克隆共用骨骼/状态 | 骨骼用 `SkeletonUtils.clone`；每条鱼独立 state/phase |
| 鱼被动画带出缸 | 根骨有位移通道 | 烘焙时移除根骨位移 |
| 贴图颜色发白 | 颜色空间或曝光不对 | baseColor 使用 sRGB；调试台复刻缸内光照 |
| 帧率明显下降 | 面数/贴图/draw call 超预算 | 先查资产体检和 draw calls，再降面或降贴图 |
| 模型体积过大 | 20k 面 + 1024 贴图用于群游鱼 | 群游鱼降到 3k–8k 面、512 贴图或程序化鱼皮 |

### 11.1 排错顺序

1. 先看资产体检，确认不是面数/贴图/动画结构问题；
2. 再看分区着色，确认不是绑定区域错；
3. 再看单条鱼的四角度和泳姿；
4. 最后才看整缸。

不要在整缸截图上猜“为什么鱼怪”，先把单条鱼拆开看。

### 11.2 一个高频误区

> “模型预览里看着挺像，应该没问题。”

模型预览通常是转台、均匀光、近距离；缸内是小尺寸、强环境光、透明玻璃、底砂反射。**两者不是同一个验收环境。** 必须用复刻缸内光照的调试台和整缸截图各看一次。

### 13.3 小丑鱼分区参数

```js
// 归一化坐标
u  = (x - minX) / spanX
yn = (y - centerY) / (spanY / 2)
zn = (z - centerZ) / (spanZ / 2)

// 分区
CAUDAL    : u > 0.78
DORSAL    : 0.13 < u < 0.75 && yn > 0.52 && abs(zn) < 0.42
PELVIC    : 0.18 < u < 0.47 && yn < -0.62 && abs(zn) < 0.50
ANAL      : 0.44 < u < 0.78 && yn < -0.62 && abs(zn) < 0.38
PECTORAL  : 0.18 < u < 0.47 && abs(zn) > 0.58 && -0.52 < yn < 0.34
BODY      : 其余
```

## 最后的原则

1. **外形优先于技术炫技**。用户能一眼看出的是鱼像不像，不是你的顶点着色器有多复杂。
2. **先验收再优化**。没有分区着色、四角度、尾拍周期、缸内近景，不要继续叠材质和动作。
3. **一套鱼一套参数**。阈值、枢轴、鳍幅、体长都不能从另一条鱼直接复制。
4. **可回退**。正式资产必须能从 `source/` 重跑；程序化备选和照片正式版分开存放。
5. **先做能跑起来的简单方案，再补细节**。但“简单”不能以牺牲外形或鳍根完整性为代价。

本指南当前只作为项目流程文档使用，暂未封装为 Skill。
