## 2026-11-19 · 为什么换回照片重建版

用户对比两版后明确选择了照片重建版：头部与身体体积更自然，鱼鳍不是规则几何片，白带宽窄变化
更像真实小丑鱼。程序化版虽然更容易分件控制，但为了动作完整性牺牲了最重要的外形观感，这个
取舍不成立。正式方案改为“用户认可的外形 + 补上可分解动作”。

### 单网格怎么继续做细腻动作

照片版只有一个 mesh，不能按对象名找鳍。`bakeSwimAttributes()` 在归一化局部坐标里按体轴、
背腹、侧向位置烘焙两个顶点属性：

- `aBody.x`：体长位置（0 吻端、1 尾端）；`aBody.y`：鳍根 0 → 鳍缘 1 的权重；
- `aRegion`：身体 / 背鳍 / 臀鳍 / 尾鳍 / 胸鳍 / 腹鳍六个区域。

当前 11,937 个顶点的分区结果：身体 5,808、背鳍 1,654、胸鳍 1,950、尾鳍 1,181、
腹鳍 807、臀鳍 537。`clownfish-debug.js` 会按区域给顶点着色，用来确认身体没有被误判成鳍。
胸鳍/腹鳍绕肩关节旋转时乘 `finRoot`，鳍根权重为 0，所以连通网格在接缝处不会被撕开。

### 材质

照片贴图把高光也烘进了颜色。`polish_photo.py` 先只把暖色像素的饱和度提回参考照片的橙色，
白带与黑缘保持不动；片元着色器再处理一次饱和橙与低饱和淡粉区域，并压住中性亮面 10%。
材质改为 `roughness 0.64 / clearcoat 0.045 / envMapIntensity 0.16`，去掉大块塑料高光。

### 验证

- 区域着色检查：六个鳍区都落在真实鳍面上，身体无彩色误判；
- 四角度 / 四泳姿相位 / 一个尾拍周期：无鳍根撕裂、无破面、无倒立；
- 缸内 7 条（银鲦 5 + 小丑鱼 2）约 53 FPS、62 draw calls，控制台干净；
- 13/13 单元测试、构建、客户端冒烟验证通过；
- `audit-fish.mjs` 按 20,000 面 / 950 KB 的英雄鱼豁免放行，结果为 PASS。

### 已知取舍

照片版是单网格、单材质：眼睛与鳍没有独立 PBR 材质，贴图里仍有少量烘焙光；换来的是明显更
自然的外形。若以后要追求全身扫描级细节，应以这版为底模重拓扑并拆分鳍片，而不是退回程序化
几何。

## 0. 旧资产为什么不行

旧版是"参考照片 + 低模"的产物：1024² 彩色贴图 + 512² 法线，10,206 面，669 KB，静态网格，泳姿靠
`texturedSwimMaterial` 在顶点着色器里做横向平移。实测截图（`docs/evidence/` 与 `.screenshots/` 旧图）暴露出五类问题：

| 问题 | 现象 | 根因 |
| --- | --- | --- |
| 白带变形 | 中间白带被拉成 S 形，黑边粗细不均 | 照片投影到低模，UV 不是按体轴展开的 |
| 眼睛是贴图 | 侧看是一个黑点，近看没有球体、没有高光 | 眼睛画在 baseColor 上 |
| 鳍像贴片 | 背鳍/尾鳍边缘发硬，胸鳍几乎看不见 | 鳍和身体同一张网格，厚度与插入点都没有做 |
| 游动像纸板 | 只有横向位移，截面不转，高光不跟着弯 | 顶点只 translate，没有把截面按切线角旋转 |
| 体积 | 单条 669 KB，整个渲染包 1.62 MB | 1024² 彩色 + 512² 法线，且照片细节大部分用不上 |

这五条里，只有"贴图细节"是照片带来的好处；其余都是"照片→低模"这条路线本身的代价。

## 1. 新资产的解剖

坐标：**X = 体长轴（头在 -X 端）**，Y = 背腹轴，Z = 侧向。几何单位是全长 0.94，入缸时由
`normalize()` 重标定到 `targetLength = 6.2 cm`。

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 体长 / 体高 | 1.95 | 含背鳍与臀鳍；参考图实测 1.95 |
| 体长轴 | X | 最长轴，`facing: -1` 把头转到 +X |
| 体高（不含鳍） | 0.335（约 42.8% 全长） | 纺锤形，头明显大于身体中段 |
| 体宽 | 0.129 全长 | 侧扁，但不至于成刀片 |
| 吻端 | x = 0 | 钝吻 + 凸出的上下唇；眼睛在 x = 0.082、y = 0.046，半径 0.034 |
| 尾柄 | x = 0.762 起 | 收细到 0.087 高（约体高 26%），尾鳍从 0.762 接上 |
| 面数 | 15,336 | 身体 9,696 / 背鳍 1,348（前后两片）/ 臀鳍 748 / 尾鳍 864 / 胸鳍 1,120 / 腹鳍 792 / 眼 768 |

### 体形

身体是 56 环 × 28 段的放样（loft）：每个环由三条剖面曲线（背线、腹线、半宽）决定，控制点写在
`PROFILE_*` 里，经过高斯平滑后采样。横截面是带轻微修正的椭圆（`z = half·sinφ·(1−0.17cosφ)`，
最宽处略低于中线），鳃盖处额外鼓起 5%。

这样做的直接好处：**改背线/腹线的三个数就能改体形**，不用回到建模软件。前面几轮调整
（头太小、尾柄太粗、体太圆）都是改这几行控制点完成的。

### 三条白带

图集里按体轴解析绘制，不是照片投影：

| 带 | 中心 u（体长） | 半宽 | 特征 |
| --- | --- | --- | --- |
| 头带 | 0.235 | 0.030 | 眼后一圈，后缘黑边 0.016 |
| 中带 | 0.600 | 0.048 | 背侧向前凸 0.020，是眼斑双锯鱼最好认的形状 |
| 尾柄带 | 0.950 | 0.024 | 窄，压在尾柄上 |

黑边不是等宽描边：白带外缘先有一段 0.003 的软过渡，再是 0.009–0.014 的黑带，黑带外再压一圈
0.02 的暗晕。白带内侧叠一层很淡的冷阴影和颗粒，避免"纯白贴纸"。

### 鳍

每种鳍都是独立的参数化面片，UV 的 **v 轴就是"从鳍根到鳍缘"**，这一条约定让着色器可以：

- **背鳍是两片，不是一整片**：前段棘鳍（x 0.290–0.512，最高 0.098）高而尖；后段软鳍
  （x 0.522–0.775，最高 0.065）低而圆；中间 0.010 的凹口让两片在轮廓上分开。
  两片合并在一个 "DorsalFin" mesh 里，仍只占一个 draw call；
- 背鳍/臀鳍：沿鳍缘做 11/15/12 根鳍条起伏，外缘随 v² 摆动；
- 尾鳍：竖直鳍基 + 扇形尾缘，完全盖住收细的尾柄（不留断口），v 方向做相位滞后的摆动；
- 胸鳍：扇形，绕肩关节做"划桨"（Y 轴后掠 + X 轴小幅翻），左右用 z 的符号区分；
- 腹鳍：挂在腹部，小幅反相摆动。

鳍的厚度是 0（单层面片 + `DoubleSide`），靠几何起伏 + 高光读成薄膜；外缘统一有一条深色鳍缘，
避免"纸片边缘"。

### 表面与雕刻

- 1024×512 图集：身体占 680×512，五种鳍各占一个岛；
- 颜色按缸内光照反推（不是抄照片屏幕色）：背 `#8c1a00` → 体侧 `#d13301` → 腹 `#f26b0a`，
  白带 `#d6d4c9`，黑边 `#080a0b`；片元里再对饱和橙区压一次 `(0.88, 0.72, 0.62)`，
  白带与黑边保持中性；
- 鳞片在颜色里是 54 行交错弧，只压 2.8%，近看才读成鳞；
- **大形体雕刻**（进几何，影响轮廓与掠射光）：身体提到 100 环 × 48 段，沿顶点法线推拉——
  鳃盖骨鼓起 + 后缘深沟、眼窝眶缘、上下唇、眉弓、下颌、颊部、胸鳍肩、肌节、鼻孔、背/臀鳍根；
- **细节法线**（不进几何）：按图集 UV 烘一张 1024×512 切线空间法线，含鳞片圆顶、侧线孔列、
  鳃盖条纹、唇/眼窝、鳍条脊；材质 `normalScale = 1.3`；
- 眼睛不是贴图：两个低模眼球 + 程序化虹膜（瞳孔 0.54R、橙红虹膜、暗色巩膜），
  `clearcoat = 1`、`roughness = 0.05`，高光由真实灯光给。

## 2. 泳姿：从"横向剪切"到"脊柱弯曲"

### 2.1 身体

旧版只把顶点沿 z 平移，截面还是原来的朝向，整条鱼看起来像被推着走。新版在顶点着色器里：

1. 以体轴坐标 u（0 吻端，1 尾柄）定义一条行进波
   `z(u,t) = 0.135·A·env(u)²·[sin(φ) + 0.16·sin(2φ+0.7)]`，`φ = ωt − 2.35u`；
2. 用 `θ = atan(∂z/∂u)` 求该处切线角；
3. 位置按 `x' = x + z·sinθ`、`z' = z·cosθ + z(u)` 变化，**截面跟着切线转**；
4. 法线用同一个 `R_y(θ)` 旋转。

第 3、4 步是"活"和"纸板"的分界：高光沿着弯曲的体表走，而不是贴在原来的表面上。

振幅包络是 `smoothstep(0.04,1,u)²`：头几乎不动，越靠尾越大。满幅时尾柄横摆 ±13.5% 体长；
悬停时 `A≈0.2`，只有 ±2.7%，主要靠胸鳍——这正是小丑鱼悬停的姿态。

### 2.2 鳍的跟随

- 尾鳍的 `aBody = 1.0`，先整体继承尾柄的位移与转角，再叠一层相位滞后 2.6 rad、幅度 6.2% 的
  摆动，所以是"被水推着甩"，不是刚体扇子；
- 背鳍/臀鳍沿体轴逐点跟随身体弯曲，再按 v² 做 0.010/0.008 的横向摆动；
- 胸鳍绕肩关节划水（±0.28 rad 后掠 + ±0.16 rad 翻），左右反相；腹鳍慢半拍；
- 所有鳍的根都埋在身体里 3–5 mm，弯到极限也看不到缝。

### 2.3 驾驶

`ClownfishPilot` 不是"沿椭圆路径走"，而是限加速度的转向：

- 状态机：`hover`（悬停 2.2–4.8 s）→ `cruise`（1.6–3.8 s）→ 偶发 `dart`（0.32–0.54 s，20 cm/s）；
- 悬停时目标点沿领地做一个慢速圆轨道（半径约 2.2 cm），保证"看起来停着"也有 0.5–0.8 cm/s 的漂移；
- 速度用一阶滞后逼近目标（`k≈2.6`），偏航角按最大角速度逼近（悬停 1.4、巡游 3.6 rad/s），
  所以不会出现瞬移式掉头；
- 转弯侧倾 `roll ∝ −yawRate`，俯仰跟着垂直速度；再叠一层与尾拍同频的 ±1.7° 偏航 / ±1.8° 侧倾，
  这是"鱼在摆"的最后一点细节；
- 两条鱼之间有软斥力（4.5 mm），四壁与水面有 3.5–5.5 cm 的软排斥，不会贴玻璃硬拐；
- 尾拍幅度/频率随实际速度走：2.1–7.7 Hz、0.16–1.0 幅度；胸鳍频率在悬停时 2.05 Hz、巡游时降到 1.15 Hz；
- 因此"停"和"游"是两套动作，而不是同一套动画放慢。

## 4. 程序化备选版：历史数据

| 指标 | 旧照片低模 | 程序化备选 |
| --- | --- | --- |
| 单条资产 | 669 KB / 10,206 面 | 541 KB / 15,336 面 |
| 渲染包 `lib/client.scene.js` | 1,616,748 B | 1,477,109 B |
| draw calls（5 银鲦 + 2 小丑鱼） | 60 | 74（每条小丑鱼 7 个 mesh） |
| 贴图 | 1024² color + 512² normal | 1024×512 颜色图集 + 1024×512 法线 |
| 泳姿 | 顶点平移 | 脊柱弯曲 + 截面/法线旋转 + 鳍铰接 |

程序化版更容易精确分件，但外形不如图片重建版自然，最终只保留为备选。它不再写入正式资产路径。

### 程序化备选版的取舍

1. **不是扫描**。身体 100×48 底模 + 沿法线推拉的体块 + 一张烘焙法线；近景能看出鳃盖、唇、
   眼窝和鳞片，但外形仍带规则放样的痕迹。
2. **阴影不跟着泳姿变形**。`castShadow` 用的是绑定姿态；6 cm 的鱼在射灯阴影里看不出来。
3. **嘴有几何唇，但没有口腔**；胸鳍是单层薄膜，靠法线贴图和深色鳍缘读成薄膜。
4. **淡水缸里的海水鱼**。这是本期的产品取舍（用户点名只做小丑鱼）。

```powershell
# 可选：重建程序化备选版（输出到 scripts/clownfish/alternates/，不覆盖正式资产）
npm run asset:clown:procedural
```

照片原始网格在 `scripts/clownfish/source/clownfish-photo-base.glb`；调色脚本
`scripts/clownfish/polish_photo.py` 只提高暖色像素的饱和度，白带与黑缘不动。

`asset:clown:procedural` 会依次尝试 `$env:PYTHON`、`python`、`py -3` 和 DSH 自带的运行时解释器；
只要其中一个能 `import numpy, PIL` 就会用它。程序化备选版的几何参数仍在 `build_clownfish.py`
顶部：`PROFILE_*`、`FIN_RECTS`、`build_fins()`、`build_atlas()`。
